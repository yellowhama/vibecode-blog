# Blog Draft — 한국어 블로그 작성

`/blog-plan`에서 설계한 서사 구조(또는 대화 컨텍스트의 설계)를 바탕으로 한국어 블로그 포스트를 작성하고 파일을 생성한다.

## 소스

- 소스 경로: $ARGUMENTS

## 프로세스

1. 대화 컨텍스트에서 서사 설계를 확인한다 (없으면 사용자에게 `/blog-plan`을 먼저 실행하라고 안내)
2. 소스 파일을 읽는다
3. 아래 레퍼런스 파일을 **반드시** 읽는다:
   - `branding/voice.md` — 톤 SSOT. 특히:
     - §1 제1원칙: 톤을 올리지 마라
     - §2 모드 A/B: 삽질기=싸지르기, 비평=각잡기
     - §5 문장 규칙: 8-15단어, self-correction, 선언문 마무리
     - §7 금지 표현 목록
     - §9 문체 4법칙
   - `branding/narrative.md` — 3막 구조 (짜증→난리→파헤침), 6비트 체크리스트
   - `branding/examples.md` — 좋은/나쁜 예시, 이야기 vs 설명 판별
   - `branding/platforms.md` — 블로그 섹션: 자기완결 섹션, 선언문 마무리
4. 기존 phase1 파일을 확인한다 — Act 번호 충돌 방지
5. 글을 쓴다
6. 파일을 생성한다:
   - 개별 씬: `easy_peasy/phase1/actN-M-ko.md`
   - 압축본: `easy_peasy/phase1/actN-ko.md` (전체를 한 파일로)
7. 사용자에게 결과를 제시한다

## 글쓰기 규칙

### 톤: 모드 A (싸지르기) 기본
- 생각 순서 그대로. 정리 안 한다.
- **한 문장 = 한 줄.** 절대 합치지 않는다.
- **3-7단어 펀치**가 기본 리듬.
- **"근데"**로 전환. "그러나/하지만" 쓰면 죽는다.
- **자문자답.** 질문하고 바로 답한다.
- **마무리는 선언문.** 짧게. 끝.
- **결론 없어도 됨.** "아직 모른다"가 유효한 결말.

### 원문 보존
- 소스 원문의 리듬(짧은 줄, 끊어 쓰기, 자문자답, 감정 터짐)을 **그대로 보존**한다.
- 요약하거나 압축하지 않는다. 원문이 3단어면 3단어 그대로.
- 설명을 이야기로 전환한다: "RAG는 ~이다" → "엄마 옷장에서 겨울코트 찾는 거"
- 각 씬은 독립적으로 읽혀야 한다 (but 전체 흐름도 유지).

### 문체 4법칙 (voice.md §9)
1. **지하실로 끌고 내려가라**: 거창한 문장은 3단어로 찢어라.
2. **고통을 가리지 마라**: 삽질, 멘붕, 포기 — 그대로 보여라.
3. **AI는 싸움 상대**: "시켰다", "던졌다", "받아쳤다" — 협업이 아니라 전투.
4. **선언문처럼 끝내라**: 마지막 문장은 짧고 단호하게.

## 절대 금지

- **금지 표현**: game-changer, deep dive, unpack, Furthermore, In conclusion, utilize, facilitate, leverage, "I think maybe...", "I write about..."
- **시간 참조**: "6개월", "X주", "months ago" — 시간 개념 자체를 빼라
- **"4줄 스펙"**: "4줄" / "네 줄" 금지. "4가지 개념" / "네 가지"로 쓴다.
- **수동태 남용**: "코드가 작성되었다" → "내가 썼다" / "AI가 썼다"
- **톤 올리기**: 구어체 → 격식체 전환 금지. 처음부터 끝까지 같은 톤.
- **광고 카피 구조**: Setup→twist→teach→CTA 금지
- **AI = 친절한 조수**: AI는 싸움 상대다. "도와줬다" 금지. "시켰다" / "던졌다".
