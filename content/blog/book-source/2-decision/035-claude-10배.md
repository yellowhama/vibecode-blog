# Claude 10배 더 쓰는 법: Anthropic이 직접 알려준 비밀

## TL;DR

- **Claude가 멍청한 게 아니다. 네 프롬프트가 멍청한 거다.**
- 톤·수량·범위·구조·Why — 이 5개만 챙기면 출력이 완전히 달라진다.
- 한 방에 끝내려다 망한다. 초안 → 수정 → 완성. 이게 답이다.

---

## 왜 이 글을 쓰나

요즘 바이브 코딩할 때 여러 모델을 돌려쓴다.

Gemini 3. OpenAI의 Codex CLI. 그리고 Claude Opus 4.6.

솔직히 말하면 **Opus 4.6이 제일 낫다.**

뭐가 다르냐?

일단 맥락을 잘 잡는다. 내가 뭘 하려는지 한 번에 알아챈다. 코드도 깔끔하게 나온다. 다른 모델들은 가끔 엉뚱한 데로 새는데, Opus 4.6은 그게 적다.

근데 문제가 있었다.

가끔 결과물이 들쭉날쭉했다. 어떤 날은 "와 이게 되네?" 싶고, 어떤 날은 "아니 왜 이러지?" 싶었다.

그러다 알게 됐다.

**Anthropic이 Claude 잘 쓰는 법을 계속 흘리고 있었다.**

블로그에. 공식 문서에. X에. 유튜브에.

12개월 동안 힌트를 뿌려놨는데, 나는 그냥 모델만 갖다 쓰고 있었던 거다.

그래서 정리해봤다.

결론부터 말하면, **모델 성능 문제가 아니었다. 내가 프롬프트를 잘못 짜고 있었던 거다.**

---

## 1. 톤: 팀원처럼 대해라

Anthropic이 첫 번째로 강조한 게 의외로 이거다.

"친절하고 명확하고 단호한 톤이 가장 좋은 결과를 낸다."

### Before

```
이 문법 고쳐 당장

```

뭐가 문제냐? Claude가 움츠러든다. 과도하게 조심스러워진다. 말이 돌아간다.

### After

```
다음 문장의 문법 오류를 검토해줘.
목표는 더 전문적이고 자신감 있게 들리게 하는 거야.

```

이건 단순한 예의 문제가 아니다.

Claude한테 **"네가 뭘 해야 하는지"를 명확히 알려주는 메타 정보**다.

팀원한테 소리 지르면서 일 시키냐? Claude도 마찬가지다.

---

## 2. 3요소: 행동동사 + 수량 + 대상

Anthropic 공식 프레임워크다. 외워라.

1. **행동동사**: Generate, Rewrite, Summarize
2. **수량**: 몇 개
3. **대상**: 누구를 위한 건지

### Before

```
블로그 아이디어 좀 줘

```

수동적이다. 구체적이지 않다. AI 슬롭 나온다.

### After

```
원격 근무가 도시 계획에 미치는 영향에 대한 블로그 제목 10개 만들어줘.
타겟 독자는 시 공무원과 부동산 개발자야.

```

왜 이게 강력하냐?

- 수량이 있으면 Claude는 "끝"이 어딘지 안다
- 대상이 있으면 어조와 정보 수준을 자동 조정한다
- 행동동사가 있으면 "작업 모드"가 고정된다

이것만으로 품질 2~3배 오른다. 진짜다.

---

## 3. 박스: 제약이 창의성을 만든다

### Before

```
미래의 탐정에 대한 단편 소설 써줘

```

가능성이 무한하다. 무한하면 뻔해진다. AI 슬롭.

### After

```
500자 이하.
스타일: 레이먼드 챈들러.
주인공: 화성에서 데이터 도난 사건을 수사하는 로봇 탐정.
금지어: '사이버'

```

이게 왜 되냐?

**빈 들판보다 잘 정의된 박스가 창의적인 결과를 낸다.**

AI는 제한 안에서 최적화된 창의성을 발휘한다. 범위가 넓으면 평균으로 간다.

---

## 4. 3단계: 초안 → 계획 → 실행

한 방에 끝내고 싶다. 나도 안다. 기분 좋다.

근데 그러면 망한다.

Anthropic이 추천하는 방식은 3단계다.

### Step 1: 초안

```
4일 근무제 장점에 대한 보고서 아웃라인 먼저 만들어줘

```

### Step 2: 수정

```
좋아. 2번 섹션에 직원 이직률 감소 내용 추가해줘.

```

### Step 3: 실행

```
이 수정된 아웃라인으로 전체 보고서 작성해줘.

```

왜 이게 강력하냐?

AI가 **중간에 방향성을 잃거나 과도한 추측을 하는 걸 막아준다.**

시간 더 걸릴 것 같지? 아니다. 리프롬프트 10번 하는 것보다 빠르다.

---

## 5. 구조: 형식을 지정해라

가장 강력한 규칙 중 하나다.

### Before

```
아폴로 미션들이랑 관련 사실 좀 알려줘

```

비구조화된 문단이 나온다. 파싱 불가.

### After

```
아폴로 15, 16, 17 미션을 마크다운 테이블로 정리해줘.
열: 발사일 / 승무원 / 주요 성과

```

AI는 "깔끔한 서술"보다 **정확한 구조적 출력**을 훨씬 잘한다.

표, JSON, YAML 같은 구조를 요구하면 품질이 확 뛴다. Anthropic 내부 실험 결론이다.

---

## 6. Why: 이유를 설명해라

### Before

```
커피 브랜드 마케팅 슬로건 5개 줘

```

맥락 없다. 브랜드 가치? 타겟? USP? 아무것도 모른다.

### After

```
새 커피 브랜드 슬로건 5개 만들어줘.

핵심:
- 소규모 독립 농장에서 윤리적으로 원두 조달
- 타겟은 환경 신경 쓰는 밀레니얼
- 품질과 지속가능성 반영해야 함

왜? 우리 브랜드 핵심이 '지속가능성'이니까.

```

Why 한 줄로 Claude는 즉시 파악한다.

"아, 감성적 톤은 이쪽이구나. 이 가치가 중심이구나."

출력 정확도 2~3배 차이 난다.

---

## 7. 길이 조절: 네가 컨트롤해라

Anthropic은 이걸 "verbosity control"이라고 부른다.

### Expert 모드

```
대학 생물학과 학생을 위해 광합성을 자세히 설명해줘.
정확성을 위해 단계별로 생각해.

```

### Brief 모드

```
광합성 설명해줘. 간결하게. 불릿포인트로.

```

### 5살 모드

```
광합성을 5살한테 설명하듯이 해줘.

```

**출력 길이와 깊이는 네가 정하는 거다.** 안 정하면 Claude가 알아서 정한다. 그게 맘에 안 드는 거다.

---

## 8. 스캐폴딩: 틀을 줘라

무조건 강한 기능이다.

### Before

```
이 기사 요약해줘

```

### After

```
다음 기사를 이 형식으로 요약해줘:

핵심 주장: (한 문장)
주요 근거: (3개)
결론: (한 문장)

[기사 붙여넣기]

```

틀을 주면 틀대로 채운다.

AI는 구조를 매우 잘 따른다. 이틀치 스트레스가 사라진다.

---

## 9. 파워워드: AI 치트코드

Claude는 AI에 대한 엄청난 양의 텍스트로 훈련됐다.

특정 단어를 쓰면 특정 행동이 활성화된다.

### Think step by step

```
Think step by step.

```

효과: 논리적 오류 급감. 계산/추론 정확도 상승. 코드 예외 상황 더 잘 커버.

### Critique your own response

```
네 응답을 비판해봐.

```

효과: 자기검증 모드 활성화. 초안에서 오류 잡아냄.

### Adopt the persona

```
[분야] 전문가 페르소나로 응답해줘.

```

효과: 도메인 특화 어휘와 프레임워크 사용.

이거 외워둬. 진짜 된다.

---

## 10. 분할 정복: 큰 건 나눠서 시켜라

Anthropic이 말한 "제일 실수 많이 하는 패턴"이다.

### Before

```
사업계획서 만들어줘

```

10페이지짜리를 한 프롬프트로? 100% 실패.

### After

**Step 1: 설계도**

```
스페셜티 커피숍 사업계획서 목차를 상세하게 만들어줘.

```

**Step 2: 섹션별**

```
Executive Summary 써줘.

```

```
시장 분석 섹션 써줘.

```

**Step 3: 통합**

```
전체 검토해서 톤 일관성 확인하고 모순 체크해줘.

```

복잡한 작업은 지휘자처럼. 파트별로 시키고, 마지막에 합쳐.

---

## 전체 적용 예시

### Before

```
스토아 철학에 대해 알려줘

```

### After

```
철학과 대학교수 페르소나로 응답해줘.

1시간 입문 강의를 준비 중이야. 학생들은 사전 지식 없음.

먼저 3개 메인 섹션으로 강의 아웃라인 만들어줘.
- 명확한 도입, 본론, 결론
- 네스티드 불릿 리스트 형식

각 주요 포인트마다:
- 핵심 스토아 철학자 한 명 (예: 세네카)
- 그의 핵심 사상 하나

톤은 접근하기 쉽고 engaging하게.

```

이게 다다.

## 결론

Claude가 말귀 못 알아듣는다고?

코드를 엉뚱하게 만든다고?

너무 장황하다고?

**대부분 모델 문제가 아니라 프롬프트 설계 문제다.**

10가지 규칙:

1. 팀원처럼 대해라
2. 행동동사 + 수량 + 대상
3. 박스를 만들어라
4. 초안 → 수정 → 완성
5. 구조를 지정해라
6. Why를 설명해라
7. 길이를 컨트롤해라
8. 틀을 줘라
9. 파워워드를 써라
10. 큰 건 나눠서 시켜라

이거 외우면 끝이다.

AI한테 일을 맡기는 게 아니라, **AI가 일하기 좋은 환경을 설계하는 것**. 그게 진짜 생산성이다.
