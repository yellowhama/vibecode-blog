# 026  Codex CLI 코드 리뷰 자동화

# 13번째 수정 - 한 곳 고치면 세 곳 터지던 날들을 끝낸 방법

## 드디어 게임이 돌아갔다

1달 걸렸다.

GitHub에서 찾은 축구 시뮬레이션 엔진을 뜯어고치고, Godot 4.4에 얹고, Rust로 계산 로직 다시 짜고. 선수가 움직인다. 공이 굴러간다. 골이 들어간다.

야호! 축구 육성 게임의 핵심이 돌아갔다.

신나서 게임을 껐다가 다시 켰다.

```
에러: WeeklyCalendar.update() failed

```

어?

메인 메뉴로 돌아가서 새 게임 버튼을 눌렀다.
버튼이 안 눌린다.

아니 뭐야?

## 화장실 누수 고치는 것 같았다

나는 분명 시뮬레이션 엔진만 건드렸다. TacticsManager.gd 파일 몇 줄 고친 게 전부다.

근데 왜 캘린더가 터지지?
왜 버튼이 안 눌리지?

정확히 화장실 누수 고치는 것 같았다.

**첫 번째 시도**: 화장실 파이프 막음 → 거실 천장에서 물이 샘
**두 번째 시도**: 거실 천장 막음 → 침대방 벽에서 물이 샘

**세 번째 시도**: 침대방 벽 막음 → 주방 싱크대에서 물이 샘

한 곳을 고치면 다른 곳이 터진다.

## 13번의 수정, 13번의 실패

기록을 남겨봤다.

```
시도 1: TacticsManager 수정 → WeekHub 에러
시도 2: WeekHub 수정 → GameManager 에러
시도 3: GameManager 수정 → PlayerStats 에러
...
시도 13: PlayerStats 수정 → TacticsManager 에러

```

13번째에 원점으로 돌아왔다.

벽을 뚫어지게 쳐다봤다.

33개의 Autoload 싱글톤이 거미줄처럼 얽혀 있었다. GameCore.gd가 WeekHub.gd를 부르고, WeekHub.gd가 TacticsManager.gd를 부르고, TacticsManager.gd가 또 GameCore.gd를 부른다.

순환 참조의 지옥이었다.

## 진짜 문제를 깨달은 순간

그때 깨달았다.

**내가 코드를 짤 줄 몰라서 문제가 아니었다.코드를 볼 줄 몰라서 문제였다.**

AI는 코드를 짜준다. "전술 시스템 만들어줘" 하면 뚝딱 만든다.
근데 그 코드가 왜 다른 곳을 부수는지는 설명 안 해준다.

필요한 건 시니어 개발자였다. 내가 뭔가 고치려 할 때마다 어깨 너머로 보면서 "야, 그거 고치면 저기 터진다"고 미리 알려주는 사람.

하지만 현실은:

- 돈 없음
- 인맥 없음
- 설명할 능력도 없음

그래서 생각했다.

**터미널에서 돌아가는 시니어를 만들면 안 될까?**
24시간 일하고, 돈 안 받고, 불평 안 하는.

## Codex CLI를 시니어 개발자로 만들기

Anthropic GitHub 리포지토리를 뒤지다가 Codex CLI로 코드 리뷰를 할 수 있다는 걸 알았다.

근데 인터넷 예제들은 전부 복잡했다. PR 만들고, Actions 설정하고, yaml 파일 짜고...

아니야. 난 그냥 터미널에서 바로 물어보고 싶어.

그래서 단순하게 접근했다.

## 첫 시도: 그냥 물어보기

터미널 열고:

```
$ codex "이 코드 리뷰해줘" TacticsManager.gd

```

Codex가 답했다:

```
코드가 깔끔하네요! 변수명을 좀 더 명확하게 하면...

```

쓸모없었다. 내가 원한 건 "이거 고치면 어디 터지는지"였는데.

## 진짜 해결책: 프로젝트 규칙 만들기

그래서 Codex한테 이렇게 시켰다:

```
$ codex "우리 프로젝트 분석해서 코드 리뷰 규칙 만들어줘.

프로젝트는 Godot+Rust 축구 게임이고
33개 싱글톤으로 돌아가고
모바일 60fps가 목표야.

.project/codex/ 폴더에 규칙 파일들 만들어줘:
- base.md (기본 규칙)
- game.md (게임 규칙)
- forbidden.md (절대 금지 패턴)

특히 forbidden.md는 내 코드 실제로 보고
위험한 패턴 찾아서 구체적으로 적어줘"

```

10분 뒤:

```
Codex: 프로젝트 분석 완료. 규칙 파일 생성했습니다.

발견된 주요 문제:
1. UI에서 시스템 직접 호출 (7곳)
2. 시간 관리 중복 (3곳)
3. 순환 참조 (12곳)

forbidden.md에 전부 정리했습니다.

```

## Codex가 찾아낸 우리 프로젝트의 지뢰들

forbidden.md를 열어봤다:

```markdown
# 절대 금지 패턴 (발견된 실제 사례)

## 1. UI에서 시스템 직접 호출

WeekHub.gd line 45에서 발견:
나쁜 예: GameCore.start_week() 직접 호출
좋은 예: EventBus.emit_signal("week_started")

이유: 한 곳 고치면 연쇄 폭발

## 2. 시간 흐름 중복 관리

GameCore.gd와 WeekHub.gd 둘 다 시간 관리 중
→ 주간 훈련이 2번 실행되는 버그 원인

## 3. 게임 루프 내 동기 I/O

SaveManager.gd line 234: _process()에서 파일 저장
→ 60fps 깨지는 원인

```

내 실제 코드를 보고 만든 거였다.

## 이제 Codex가 진짜 시니어가 됐다

터미널에서:

```
$ codex "TacticsManager.gd 리뷰해줘"

```

Codex:

```
🔴 위험 발견:

Line 45: GameCore.current_week 직접 참조
- 문제: WeekHub도 current_week 관리함
- 영향: 시간 2배속 버그 발생 예정
- 해결: EventBus.get_current_week() 사용

이대로 실행하면 WeekHub.gd에서 터질 확률 90%

```

드디어! "이거 고치면 저기 터진다"를 미리 알려준다.

## 매일 쓰는 세 가지 질문

### 1. 파일 수정 전에 물어보기

```
$ codex "TacticsManager.gd 수정하려는데 위험한 거 있어?"

Codex: Line 45, 89, 134가 다른 파일이랑 얽혀있어.
특히 45번은 WeekHub 터뜨릴 수 있으니 조심해.

```

### 2. 수정 후에 확인하기

```
$ codex "방금 고친 파일들 확인해줘"

Codex: 3개 파일 검토:
- TacticsManager.gd: 안전
- WeekHub.gd: 위험 (EventBus 안 씀)
- GameManager.gd: 경고 (에러 처리 없음)

```

### 3. 주기적으로 전체 점검

```
$ codex "src/core/ 폴더 전체 구조 문제 있어?"

Codex:
구조적 문제 3개:
1. 시간 관리가 3곳에 분산됨
2. 순환 참조 12개 발견
3. 같은 계산 로직 5번 중복

```

## 실전: 13번째 벽을 0번으로

예전 방식:

```
TacticsManager 수정
→ 실행
→ WeekHub 터짐
→ WeekHub 수정
→ 실행
→ GameManager 터짐
→ (3시간 후 포기)

```

새 방식:

```
$ codex "TacticsManager 수정하려는데 뭐 조심해야 돼?"

Codex: WeekHub랑 GameCore 터질 수 있어.
      같이 고쳐야 할 곳 3군데 알려줄게...

(30분 만에 완료)

```

## 3주 사용 후 실제 변화

**전:**

- 수정 시간: 평균 3시간
- 에러 발생률: 90%
- 포기 횟수: 주 2-3회
- 스트레스: 극심

**후:**

- 수정 시간: 평균 30분
- 에러 발생률: 10%
- 포기 횟수: 0회
- 스트레스: 거의 없음

가장 큰 차이:
**수정 후 에러 고치기 → 수정 전 에러 예방**

## 코드를 못 짜도 괜찮다, 못 읽는 게 문제다

바이브 코딩의 진짜 문제:

- 코드 못 짜는 거 ❌
- 만든 코드 이해 못하는 거 ⭕

AI가 코드 짜줌 → 시니어가 검토해야 함
시니어 없음 → Codex를 시니어로 만들면 됨

필요한 거:

- 시간: 10분
- 스킬: 터미널에서 타이핑

이제 코드 고칠 때마다 떨지 않는다.
Codex가 "그거 고치면 여기 터져"라고 미리 알려주니까.

13번째 벽은 다시 오지 않았다.
