## Opal, 지금 AI 판에서 어디에 서 있는 툴인가?

### vs ChatGPT / Claude

ChatGPT와 Claude는 **대화형 AI**다. 질문하면 답변한다. 코드를 달라고 하면 코드를 준다. 하지만 그걸 **직접 실행하거나 앱으로 만들어주지는 않는다**.

Opal은 다르다. "SEO 콘텐츠 라이터 만들어줘"라고 하면:

- 워크플로우를 설계하고
- UI를 만들고
- 실행 가능한 미니앱을 뽑아준다

**"답변"이 아니라 "결과물"이 나온다.**

### vs n8n / Zapier / Make

n8n, Zapier, Make는 **워크플로우 자동화 툴**이다. 강력하지만 학습 곡선이 있다. 노드 연결하고, 트리거 설정하고, API 키 넣고.

Opal은 그냥 **말로 설명하면 된다**. "이메일 오면 슬랙에 알림 보내줘" 이런 식으로. 노코드를 넘어서 **노터치**에 가깝다.

단, 복잡한 멀티스텝 자동화나 외부 API 연동은 아직 n8n/Zapier가 낫다. Opal은 **빠른 프로토타이핑과 단순 워크플로우**에 최적화되어 있다.

### vs Claude Artifacts / GPT Canvas

Claude의 Artifacts나 GPT의 Canvas도 "만들어주는" 기능이 있다. 하지만 이건 **대화 안에서 임시로 만들어지는 것**이다.

Opal은 **독립적인 미니앱**을 만든다. 저장되고, 공유되고, 다른 사람이 쓸 수 있다. "remix" 기능으로 남이 만든 앱을 복사해서 커스터마이징할 수도 있다.

## 실제로 뭘 만들 수 있나: 4가지 예시

### 1. SEO 콘텐츠 라이터

**용도**: 클라이언트 블로그 운영, 니치 사이트 운영하는 1인 에이전시

**입력**: 키워드 "SEO agency Birmingham"

**Opal이 만든 워크플로우**:

1. 키워드 입력 받기
2. SEO 베스트 프랙티스 리서치
3. 경쟁사 분석
4. SEO 최적화 콘텐츠 생성
5. HTML로 렌더링

**출력**: 141단어 블로그 포스트, 1분 만에 완성

### 2. 비디오 스크립트 + 썸네일 생성기

**용도**: 유튜버, 콘텐츠 크리에이터의 기획 시간 단축

**입력**: 토픽 "Google Opal"

**출력**:

- 비디오 스크립트
- 3개의 훅
- 타이틀
- 썸네일 컨셉
- 실제 썸네일 이미지
- AI 생성 비디오

### 3. 팟캐스트 게스트 매처

**용도**: B2B 세일즈, 네트워킹, 인플루언서 아웃리치 자동화

**입력**: 니치 + 팟캐스트 이름

**출력**:

- 10명의 추천 게스트

## Opal 사용법: 3단계

### Step 1: 아이디어를 타이핑한다

```
"AI SEO 콘텐츠 라이터 만들어줘"

```

기술적인 얘기 하지 마라. **뭘 원하는지**만 말해라.

### Step 2: Opal이 워크플로우를 짠다

Opal이 알아서:

- 필요한 단계를 설계하고
- 각 단계의 프롬프트를 만들고
- UI를 구성한다

### Step 3: 테스트하고 개선한다

결과물이 맘에 안 들면 수정 요청:

```
"카피라이팅 스타일을 더 직설적으로 바꿔"
"3학년 수준의 쉬운 언어로 써"
"내 회사 정보 반영해서 CTA 넣어"

```

Opal이 워크플로우를 수정한다.

## Opal 스택 프레임워크

### 1. 결과물 정의 (Define)

기술 얘기 말고 **최종 결과물**이 뭔지 말해라.

```
"Google Opal에 대한 블로그 포스트가 필요해.
뭔지, 왜 중요한지, 어떻게 쓸 수 있는지.
1000단어, 읽기 쉽게, 실제 예시 포함."

```

### 2. 컨텍스트 제공 (Context)

누구인지, 청중이 누군지, 스타일이 뭔지.

```
"내 청중은 1인 기업가들이야.
똒똒하지만 기술적이진 않아.
친구한테 말하듯이 쉽게 써줘."

```

### 3. 검색하게 놔둬 (Search)

Opal에게 최신 정보 검색, 예시 찾기, 데이터 가져오기를 시켜라.

### 4. 정제하고 반복 (Refine)

결과물 보고 뭘 고칠지 말해라. Opal이 수정한다.

**Define → Context → Search → Refine**

## 한계와 주의점

### 되는 것

- 빠른 프로토타이핑
- 단순 워크플로우 자동화
- 콘텐츠 생성 (텍스트, 이미지, 비디오)
- 아이디어 검증
- 미니앱 공유 및 remix

### 안 되는 것 (아직)

- 복잡한 멀티스텝 자동화 (n8n/Zapier가 나음)
- 외부 API 연동 (제한적)
- 프로덕션급 앱 배포
- 데이터베이스 연동
- **커스텀 도메인 연결 불가**
- **독립 앱으로 내보내기 불가** (Opal 플랫폼 안에서만 작동)
- **엔터프라이즈급 배포 부적합**

### 주의점

- 100% 완벽하게 작동하지 않을 수 있다. 테스트 필수
- 결과물 품질은 프롬프트에 달렸다
- 민감한 데이터 입력 주의
- 베타 단계라 기능이 자주 바뀔 수 있음

## 흔한 질문들

### "기술 잘 모르는데 할 수 있나?"

된다. Opal의 핵심은 **"뭘 원하는지만 말하면 된다"**는 거다. 어떻게 작동하는지 몰라도 된다.

### "Zapier/n8n 쓰는데 왜 Opal을 써야 하나?"

용도가 다르다.

- **Zapier/n8n**: 복잡한 자동화, 외부 서비스 연동, 프로덕션
- **Opal**: 빠른 프로토타이핑, 아이디어 검증, 단순 워크플로우

둘 다 쓰면 된다. Opal로 빠르게 검증하고, 되면 n8n으로 본격 구축.

### "무료라는데 진짜 무료인가?"

현재 기준 완전 무료다. Google 계정만 있으면 된다. 다만 베타 단계라 향후 유료화 가능성은 열려 있다.

### "Claude Code랑 뭐가 다른가?"

- **Claude Code**: 터미널 기반, 실제 코드 생성, 프로덕션급 개발
- **Opal**: 웹 기반, 노코드 미니앱, 빠른 프로토타이핑

Claude Code는 "개발"이고, Opal은 "자동화/프로토타이핑"이다.

## 앞으로의 관전 포인트

Opal은 2025년 7월에 미국 베타로 시작해서, 11월에 160개국으로 확장한 따끈따끈한 툴이다.

관전 포인트:

1. **외부 API 연동**이 확장되는가
2. **독립 앱 내보내기**가 가능해지는가
3. **유료화** 시 가격 정책은 어떻게 되는가
4. **Gemini 모델 업그레이드**가 Opal 성능에 얼마나 영향을 주는가

앞으로 3개월 동안 실전 케이스가 얼마나 쌓이는지가 진짜 평가 기준이 될 거다.
