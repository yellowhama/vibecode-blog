# UX Is Not Design

UX.

"Isn't that a design term?"

No.

---

Using an iPhone.
Unlock. Tap the app. Done.

Good UX.

Using an iMac.
Want to do something? Settings three times. Permission prompt. Update required.

Bad UX.

UX is not design.
UX is this.

**The experience you desperately want.**

---

I open my laptop at a cafe.
Need a file from my desktop at home.

It's not there.

"Shit."

That moment.
Eliminating that moment.
That's my UX.

Pretty buttons aren't UX.
Matching colors aren't UX.

"I opened my laptop at a cafe and the file was there."
That's UX.

"Shit" turning into "oh, nice" — that's UX.

---

So how is this different from a spec?

Specs define what to build.
UX defines how you experience it.

"File sync" is a spec.
"Open it at the cafe and it's already there" is UX.

Same feature.
One is system perspective. The other is human perspective.

---

Build from the system perspective only, this happens.

"File sync complete."
"Sync success: 1,247 files."
"3 conflicts — resolve manually."

The feature runs.
But it's infuriating.

Resolve three conflicts manually?
At a cafe?
On a laptop?

Feature exists. Experience doesn't.

---

Build from the human perspective, this happens.

Open the laptop at a cafe.
File's there.
Done.

Conflicts? Handled automatically.
1,247 files? Don't need to know.
Sync success message? Don't need to see it.

"It's there."
That's all.

---

So. XDD.

Specs (FDD) set "what to build."
Process (SDD) set "in what order."
Structure (DDD) set "where it goes."
Tests (TDD) confirmed "is it correct."

But "is this what I wanted?" — not yet.

XDD.
UX-Driven Development.

Code is the AI's job.
I design the experience.

---

A non-developer can't do code review.
Can't read code.

But a non-developer can do experience review.

"Opened it at the cafe. Is the file there?"
There? Pass.
Not there? Fail.

Didn't read a single line of code.
But answered "is this what I wanted?"

That's the non-developer's ultimate weapon.
Not code review. **Experience review.**

---

If the spec is a map.
UX is the feeling at the destination.

Followed the map to Seoul.
Standing at Seoul Station thinking "wait, this isn't where I wanted to be."
The map wasn't wrong. The destination was wrong.

Spec can be right and UX can still be wrong.
Everything falls apart.

You don't write UX before the spec.
You write the spec, then verify it with UX.

"Is this the feeling I was after?"

Yes? Go.
No? Fix.
