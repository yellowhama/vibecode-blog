# From Letters to KakaoTalk

There were letters.
Buy a stamp, seal the envelope, drop it in the mailbox.

There were telegrams.

There were phones.
"Operator, connect me to the Kims."

Then you dialed the number yourself.

Now?

Fire off a text.

---

All the same thing: "send a message."

The tech is wildly different.
A mailbox and KakaoTalk are completely different systems.

But to the person sending? Same thing.
"Get my words to someone."

Only difference is how easy it is.

---

Same with what I'm building.

The goal isn't feature completion.
It's the UX I described at the start.

"Multiple computers. One experience. Easy."

The moment that's felt even once.
That's the MVP.

---

Doesn't have to do everything.
File sync doesn't have to be perfect.
GPU sharing can wait.
Auto-recovery can wait.

But once.

Send a job from my laptop to the desktop at home.
Get the result back.

"Oh. It works. This is easy."

When that feeling arrives.
That's the MVP.

Everything else gets bolted on after.

---

Translate MVP as "minimum viable product" and you fall into a trap.

"Minimum" — so you make a feature list.
"This feature too. And that one. But minimum."

Minimum becomes ten features.
Build ten things. Blow up again.

MVP isn't the minimum number of features.

**MVP is the minimum experience.**

Feel it once and that's the MVP.
Even if there's only one feature.
Imperfect. Rough. Ugly.

"Oh. It works."

That one line is enough.

---

Here's the summary.

In the beginning, there was frustration.

Frustration's true identity: "the UX I want doesn't exist."

So I decided to build it.

Turned frustration into questions.
Threw the questions at AI.
AI gave boundaries, not answers.
Organized the boundaries. A spec emerged.
Picked the shortest path from the spec. Found the MVP.

That order.

> Frustration → UX → Questions → Conversation → Research → Spec → MVP.

---

That's Phase 1.

Decided what to build. Spec. FDD.
Decided the sequence. Process. SDD.
Decided the placement. Structure. DDD.
Confirmed it's correct. Verification. TDD.
Confirmed it's what I wanted. Experience. XDD.

```
Frustration becomes the spec.         — FDD
The spec becomes a system.            — SDD
The system gets a map.                — DDD
The map gets verified.                — TDD
Verification meets experience.        — XDD
```

---

I'm not a developer.
Can't read code.
Still can't.

But I know one thing.

I don't need to read code.

AI writes the code.
I design the experience.

Tests confirm the code is correct.
I confirm the experience is right.

"Opened it at the cafe. Is the file there?"
There? Done.
Not there? Do it again.

---

Better prompts aren't the answer.
Better AI tools aren't the answer.

"What to build" is the answer.
"How it should feel" is the answer.

And that answer doesn't come out clean.

You get pissed.
Ask questions.
Fight.
Organize.

Specs come from the grind.
Experience gets confirmed on top of the spec.
