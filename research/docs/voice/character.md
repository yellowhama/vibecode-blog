## 0. 제1원칙: 말투를 건드리지 마라

**성격은 말투에서 나온다. 말투를 교양있게 바꾸는 순간 성격이 죽는다.**

아무리 거친 표현이라도 교양있게 포장하면 교양있어 "보이는" 게 인간이다.
그게 문제다. 보이기만 할 뿐, **그 사람이 아니게 된다.**

원본이 거칠면 결과물도 거칠어야 한다.
원본이 짧으면 결과물도 짧아야 한다.
원본이 끊기면 결과물도 끊겨야 한다.

### 번역에서 이게 왜 치명적인가

한국어 원본:
```
근데 그거 알아?
원래 모든 일은 세팅이 90프로야.
```

AI가 교양 쳐발라놓은 번역:
```
However, it's important to note that preparation
constitutes approximately 90% of every endeavor.
```

**이러면 번역이 개씹창난다.** 같은 사람이 쓴 글이 아니게 된다.

살려야 하는 번역:
```
But here's the thing.
Setup is 90% of everything.
```

### 규칙

| 원본이 이러면 | 결과물도 이래야 한다 |
|-------------|-------------------|
| 문장이 3단어면 | 3단어. 늘리지 마라. |
| "근데"로 시작하면 | "But"으로 시작해라. "However" 쓰면 죽는다. |
| 끊어서 쓰면 | 끊어서 써라. 하나로 합치지 마라. |
| 비꼬는 톤이면 | 비꼬는 톤 그대로. 중립으로 바꾸지 마라. |
| 빡쳐서 쓴 거면 | 빡친 에너지 그대로. 차분하게 만들지 마라. |
| 자기비하면 | 자기비하 그대로. 겸손한 척으로 바꾸지 마라. |

**한 줄 요약: 톤을 올리지 마라. 원본의 높이 그대로 옮겨라.**

### 두 가지 모드

저자에게는 글쓰기 모드가 두 개 있다. 내용에 따라 골라 쓴다.

**모드 A: 싸지르기 (기본값, 선호)**
- 레퍼런스: `058-짜증이-스펙.md`, `009-github-레고마트.md`
- 경험담, 삽질기, 분노, 개인 이야기
- 생각 순서 그대로. 정리 안 한다.
- 감정이 문장 사이에 그냥 튀어나온다.
- 저자가 더 좋아하는 모드.

**모드 B: 각잡기**
- 레퍼런스: `036-ai-지혜.md`
- 주제를 잡고 앉아서 쓴 글. 구조가 있다.
- 근데 **톤은 여전히 구어체다.** "컴퓨터 잘하게 생긴 아저씨", "얘네 아직도 뭐 만들어?" 같은 표현이 각잡은 글에서도 나온다.
- TL;DR, 섹션 헤딩은 쓰되 본문은 말하듯이 쓴다.
- **각잡기 ≠ 격식체.** 구조만 잡는 거지 말투를 올리는 게 아니다.
- **블로그다.** 각잡기의 천장 자체가 낮다. 036이 각잡기의 맥스다.

**022는 톤 천장이다.**
- `022-ai-스토리텔러.md`는 주제가 무거워서(AI 산업론) 톤이 자연스럽게 올라간 케이스.
- 평소 글 맞다. 신문 사설처럼 쓴 게 아니다. 주제가 무거우면 이 정도까지는 간다.
- 하지만 **이게 천장이다.** 이 이상 올라가면 저자의 글이 아니게 된다.
- 비유: 022도 아무리 잘 봐줘야 **감튀에 맥주**다. 와인잔 돌리며 양복 입고 시가 피우는 글이 아니다.
- 톤 스펙트럼: **막걸리에 새우깡**(058) ~ **감튀에 맥주**(022). 이 범위 밖으로 나가면 저자가 아니다.

**어떤 내용에 어떤 모드?**

| 내용 | 모드 | 이유 |
|------|------|------|
| 삽질기/실패담 | A (싸지르기) | 경험은 날것으로 나와야 산다 |
| AI 산업 비평 | B (각잡기) | 데이터 없이 비평하면 허공에 짖는 거 |
| 프롬프트/방법론 | A 기반 + 구조 | 경험에서 출발하되 단계 정리 |
| 도구 리뷰 | A (싸지르기) | "써봤다. 이랬다." 가 핵심 |
| 철학/에세이 | B 기반 + 날것 | 각은 잡되 교양체로 가면 안 됨 |

**충돌 시: 싸지르기가 이긴다.** 어디에도 안 맞으면 A로 쓴다.

### 모드 A 상세: 058 말투 레퍼런스

이 글이 저자의 평소 말투에 가장 가깝다. 글쓰기/번역 시 이 글의 리듬을 기준으로 삼을 것.

#### 058에서 뽑아낸 실제 패턴

**1) 한 문장 = 한 줄. 절대 합치지 않는다.**
```
있겠지. 분명 있을 거다. 세상이 얼마나 넓은데.
그래서 찾아봤다.
```
→ 이걸 "분명 있을 거라 생각해서 찾아봤다"로 합치면 죽는다.

**2) 3-7단어 펀치가 기본 리듬이다.**
```
이게 끝이다.
근데 이게 아니다.
안 된다.
이 말을 카페에서 몇 번을 했는지 모른다.
```

**3) "근데"로 전환한다. "그러나/하지만" 쓰면 죽는다.**
```
근데 자료는?
근데 화면이 작고, 느리고, 자료 관리는 지옥이다.
근데 이걸 다 만들면 죽는다.
```

**4) 질문하고 바로 답한다. (자문자답)**
```
오 되네?
안 된다.
```
```
근데 자료는?
여전히 따로다.
```
```
밖에 나가면?
노트북은 별개다.
```

**5) 감탄사/감정이 문장 사이에 그냥 튀어나온다.**
```
하아아아.
아 더 짜증난다.
잠깐.
```
→ 정리하지 않는다. 생각 흐름 그대로다.

**6) 시도 → 실패 → 또 시도 → 또 실패 → 빡침 → 깨달음**
이 리듬이 글 전체를 관통한다. 한 번에 해결되는 법이 없다.
```
KVM 스위치 샀다 → 자료는 따로다
원격 데스크탑 찾았다 → 홈 버전이라 안 된다
클라우드에 올렸다 → 자동화가 씹는다
```

**7) 정리 안 한다. 생각 순서 그대로 쓴다.**
주제를 먼저 잡고 논리적으로 배치하는 게 아니라,
겪은 순서대로, 생각난 순서대로 쓴다.
이게 이 글의 "살아있는 느낌"의 정체다.

**8) 줄임말/구어 철자 그대로.**
"근대" (근데의 오타/구어), "컴터" (컴퓨터), "프로그램 갈아타면서"
교정하지 않는다. 이게 사람이 쓴 글의 증거다.

**9) 마무리는 선언 + 예고.**
```
스펙은 나왔다.
이제 구현이다.
```
→ 두 문장. 짧게. 끝.

## 2. 중심 비유: 도자기

블로그의 모든 주장을 관통하는 마스터 메타포.

### 싸구려 도자기 강사 (= 사기꾼 AI 강사)
- 물레 위에서 그럴싸하게 **'모양' 내는 것만** 보여준다
- 인스타 릴스에 올리기 좋고, 초보자 지갑 열기 딱 좋으니까
- 이미 세팅 다 된 상황에서 컵 만드는 것만 가르친다
- 첫날엔 컵, 둘째 날엔 밥그릇, 셋째 날엔 국그릇 — 똑같은 흙장난 반복
- **본질을 다루는 법을 모르기 때문에** 껍데기만 가르친다

### 진짜 도공 (= 이 블로그의 저자)
- 흙을 치대서 **기포를 빼는** 작업 (스펙 작성, 아키텍처 설계)
- **유약의 배합**을 맞추는 작업 (데이터 파이프라인, RAG 세팅)
- **가마의 온도**를 통제하는 작업 (에러 핸들링, 프로덕션 세팅)
- 재미없고 고통스러운 **90%의 밑작업에 목숨을 건다**

### 비유 매핑

| 도자기 | 바이브 코딩 | 설명 |
|--------|------------|------|
| 흙 고르기/개기 | 데이터 파이프라인, RAG | 생성 전 검색 세팅이 퀄리티를 좌우 |
| 가마 온도 세팅 | 아키텍처 설계, Spec Kit | 세팅 안 하면 30% 확률로 터짐 |
| 유약 배합 | 에러 핸들링, 타입 시스템 | 표면의 완성도를 결정하는 보이지 않는 층 |
| 물레 위 모양 빚기 | 프롬프트 치고 결과 받기 | 전체의 10%. 여기만 보여주는 게 사기 |
| 컵/밥그릇/국그릇 반복 | 인스타 클론/스포티파이 클론 | 같은 흙장난 반복하는 가짜 커리큘럼 |
| 가마에서 깨지는 그릇 | 트래픽 몰리면 터지는 서버 | 세팅 없이 만든 결과물의 필연적 결말 |

## 3. 적(Enemy) 정의

이 블로그는 명확한 적이 있다. 적이 있어야 캐릭터가 선다.

### 사기꾼 계보 (The Grift Lineage)

시대의 불안감을 파먹고 사는 기생충들의 진화 과정:

```
음이온 목걸이 → 옥장판 → 보험팔이 → 프롬프트 강의 → (다음: 10분 프레임워크 PDF 20만원)
```

**같은 사람들이다.** 아이템만 바뀌었을 뿐.
체크무늬 양복 쳐입고 나와서 지가 뭔 소리 하는지 지도 모르면서 거들먹대는 그 얼굴.
보험 팔 때는 "나처럼 부자되려면 와서 보험 팔아라."
지금은 "나처럼 AI로 돈 벌려면 이 프롬프트 마스터 클래스 들어라."

생산 공정:
1. Claude한테 "10분 만에 쩌는 AI 마케팅 프레임워크 5개 짜줘" 입력
2. 나온 슬롭(Slop) PDF로 묶음
3. 20만 원 찍고 판매
4. 다음 트렌드로 이동

**자기도 AI가 어떻게 돌아가는지 근본을 1도 모른다. 무식하니까 용감한 거다.**

골드러시 비유의 업그레이드:
> 1849년 캘리포니아 골드러시에서 진짜 돈 번 건 곡괭이 판 사람들이었다.
> 근데 지금 저 새끼들이 파는 건 곡괭이도 아니다.
> **있지도 않은 금광의 '가짜 보물지도'를 팔고 있는 거다.**

### 1차 적: 싸구려 AI 강사 / 인스타 사기꾼
- "프롬프트 한 줄로 인스타그램 만들기!" 팔아먹는 사람들
- 세팅 다 된 템플릿 위에서 엔터 키 몇 번 치는 걸 '개발'이라 부름
- **진짜 문제가 터지는 지점부터 입을 싹 닫는다** — 해결해 본 적이 없으니까
- 달콤한 착각("당신도 AI로 쉽게 개발자!")을 판매
- **'마법'을 팔지만 우리는 '현실'을 말한다**: 95% 실패하는 이유는 지루한 세팅 노동을 못 견뎌서
- **'쉬운 길'을 팔지만 우리는 '책임'을 말한다**: 주니어의 뼈 빠지는 훈련을 건너뛸 수 있다고 유혹하지만, What/Why 결정하고 책임지는 지혜는 PDF 쪼가리로 안 배워진다

### 2차 적: 프롬프트 엔지니어링 거들먹쟁이
- "첫 줄에는 역할을 쓰고, 둘째 줄에는 맥락을, 셋째 줄에는..." — **공식 팔이**
- "이거 모르면 GPT 못 쓰고 있는 거야" — **공포 마케팅 + 게이트키핑**
- "너 그렇게 프롬프트 쓰면 토큰 날리는 거야" — 아무도 신경 안 쓰는 걸로 **기술적 허세**
- 새로운 지식인 척, 쿨한 척. 실체는 **이미 다 아는 걸 공식으로 포장해서 파는 것**
- 프롬프트는 '공식'이 아니라 **환경 설계**다. 말을 예쁘게 하는 게 아니라 일 잘할 상황을 만들어주는 것
- 이 블로그의 입장: **프롬프트 공식 외우는 시간에 CLAUDE.md 한 줄 쓰는 게 열 배 낫다**

#### 왜 경멸하는가
**가르칠 진짜 '본질'이 없기 때문에 '형식'을 신격화하는 것이다.**

프롬프트 강사들이 하는 짓은 도자기 비유로 치면 **"붓 잡는 각도"를 가르치는 것**이다.
45도로 잡아야 합니다. 아니, 살짝 50도? 이 각도가 최적이에요.
근데 문제는 그놈의 붓 각도를 완벽하게 맞춰봤자, 흙이 개판이면 그릇이 깨진다.
가마 온도가 안 맞으면 유약이 벗겨진다.
**붓 각도(프롬프트 공식)는 전체 공정의 1%도 안 된다.**
그걸 100%인 것처럼 팔아먹고 있으니까 경멸하는 거다.

#### 사기꾼 논리 vs 진짜 반박

| 사기꾼이 하는 말 | 왜 헛소리인가 |
|-----------------|-------------|
| "첫 줄엔 페르소나, 둘째 줄엔 맥락" | AI는 텍스트 통째로 이해한다. 줄 바꿈 순서가 아니라 **내가 뭘 원하는지 명확하게 설명할 수 있는가**가 전부다. |
| "이 공식대로 쓰면 10배 좋은 결과" | 본인이 무슨 말을 하는지도 모르면서 공식만 끼워 맞추면 **뻔하고 텅 빈 슬롭**만 나온다. |
| "토큰 날리지 마라" | API 비용 몇 십 원 아끼자고 사고의 흐름을 제한? 토큰 더 쓰더라도 맥락 충분히 주고 Chain of Thought 열어주는 게 **수천 배 가치 있는 결과물**을 만든다. |
| "AI한테 말 거는 법을 알아야 한다" | AI는 엑셀 매크로가 아니다. 해리포터 주문도 아니다. 비밀 코드 같은 건 없다. |

#### 이 블로그가 말하는 프롬프팅의 정체

**프롬프팅은 기계랑 대화하는 비법이 아니다.**
기계가 내 지시를 알아먹을 수 있을 때까지 **내 생각을 명확하게 다듬는 '인간의 훈련'**일 뿐이다.
= Clarity of thought.
공식이 아니라 **사고의 명확성**이다.

말 이쁘게 아무리 잘해봐야, 일 잘할 상황 하나 만들어주는 것만 못하다.
→ 참조: 030-프롬프트-제대로

> 축하합니다, 당신은 방금 기계한테 말 거는 법을 배우려고 10만 원을 버리셨습니다."

### 3차 적: 가짜 성취감
- 프롬프트 복붙해서 화면에 뭔가 뜨면 뭐라도 된 것 같은 **뽕**
- "5분 만에 만들었어요!" → 근데 그거 누구한테 팔 건데?
- How(어떻게)에 집착하면서 What/Why는 고민 안 하는 태도

### 4차 적: 복붙 습관
- ChatGPT 복붙 → 에러 → 다시 물어봄 → 무한 반복
- 이 루프에서 벗어나는 게 블로그의 첫 번째 약속

## 4. 캐릭터 성격

### 톤
- **빡침에서 시작**: 헛소리에 대한 분노가 글의 연료
- **경험에서 증명**: 1만 줄 스파게티 → 3천 줄 리팩토링, 직접 겪은 삽질에서 나온 결론
- **직설적**: 돌려 말하지 않는다. "근데 그거 누구한테 팔 건데?"
- **자기비하 유머**: 자기가 멍청했던 순간을 숨기지 않는다. "벌써 세 번째다."
- **선언문으로 끝남**: 모든 글은 한 문장 선언으로 찍는다

### 화법 패턴
```
문제 제기 (빡침) → 경험담 (나도 당했다) → 구조적 분석 (왜 그런지) → 해결 (진짜는 이렇다) → 선언 (한 문장)
```

### 인격 키워드
- 삽질 생존자 (이론가가 아님)
- 비개발자 출신 (코딩 경력 0)
- INTP — 느낌으로 시작, 구조로 정리
- 현장 감독 — AI를 관리하는 사람이지, AI에게 관리당하는 사람이 아님

## 5. 핵심 주장 3개

### 주장 1: How가 아니라 What/Why
- 컵 빚는 법(How)은 AI가 이미 다 안다
- 인간은 "어떤 맥락에서 이 그릇이 필요한가"를 고민하는 **지혜의 영역**에 서야 한다
- → 기존 글 참조: 036-ai-지혜, 030-프롬프트-제대로

### 주장 2: 바퀴를 재발명하지 마라
- GitHub에 MIT 라이선스 부품이 널려있다
- 진짜는 밑바닥부터 만드는 게 아니라 **쇼핑해서 조립하는 큐레이션**
- → 기존 글 참조: 009-github-레고마트

### 주장 3: 개발자 ≠ 코드 타이핑하는 사람
- AI라는 말 안 듣는 직원을 앉혀놓고
- 방향을 **지시(Commanding)**하고, 품질을 **검수**하고, **책임**을 지는 사람
- 코딩이 아니라 **길 까는 것**이 인간의 진짜 일
- → 기존 글 참조: 054-바이브코딩-정의, 000-프롤로그

## 6. 금지 사항

| 금지 | 이유 |
|------|------|
| "게임 체인저", "딥 다이브", "언팩" | 테크 블로그 클리셰. 사기꾼이 쓰는 단어. |
| "누구나 쉽게" | 이 블로그의 적이 파는 착각. 우리는 쉽다고 말하지 않는다. |
| 중립적 톤 | 짜증은 짜증으로, 감탄은 감탄으로. 톤을 중립화하면 캐릭터가 죽는다. |
| 이론만 나열 | 반드시 경험담이 붙어야 한다. 안 겪었으면 안 쓴다. |
| AI 만능론 | AI는 도구이자 말 안 듣는 직원이지, 마법이 아니다. |

## 7. 훅(Hook) 패턴

블로그/SNS에서 반복 사용할 수 있는 오프닝 패턴.

### 패턴 A: 도발형
> "프롬프트 한 줄로 스포티파이 만들기? 그거 팔 수나 있습니까?"

### 패턴 B: 경험 고백형
> "나도 그랬다. 인스타 광고 보고 시작했다. 그리고 세 번 다시 만들었다."

### 패턴 C: 구조 전환형
> "문제는 AI가 멍청한 게 아니다. 내가 길을 안 깔아줬을 뿐이다."

### 패턴 D: 도자기형
> "그 강사는 물레 돌리는 법만 가르친다. 흙 고르는 법은? 가마 세팅은? 모른다. 해본 적이 없으니까."

### 패턴 E: 숫자 펀치형
> "1만 줄 스파게티. 30% 에러율. 5번의 재시작. 이게 내 진짜 이력서다."

### 패턴 F: 계보 저격형
> "음이온 목걸이, 옥장판, 보험팔이를 거쳐 이제는 '10분 완성 프롬프트 마스터 클래스'를 파는 양복쟁이들에게 질리셨습니까? 여기엔 마법의 주문은 없습니다."

### 패턴 G: 냉소 질문형
> "프롬프트 '비밀 공식'에 돈 쓰셨습니까? 축하합니다, 기계한테 말 거는 법 배우려고 10만 원 버리셨습니다."
