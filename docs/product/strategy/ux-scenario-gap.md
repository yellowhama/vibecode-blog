# /os 랜딩 페이지 UX 시나리오 부재 분석

> 작성일: 2026-02-22
> 용도: 랜딩 페이지 개선 방향 — "이게 뭔지"에서 "이걸 쓰면 뭐가 달라지는지"로
> 상태: 분석 완료, 구현 대기

---

## 문제

현재 `/os` 랜딩 페이지는 **"이게 뭔지"**는 설명하지만, **"내가 이걸 깔면 뭐가 달라지는지"**가 없다.

아예 모르는 사람이 읽으면:

> "MUSU는 AI를 통제하는 OS입니다. 보안도 되고 토큰도 아끼고..."
>
> → "그래서... 이거 깔면 내 화면에 뭐가 뜨는데?"
> → "Cursor 켜면 뭐가 달라지는데?"
> → "나는 뭘 하는 건데?"

---

## 현재 페이지가 하는 말 vs 빠진 것

| 현재 섹션 | 하는 말 | 빠진 것 |
|-----------|---------|---------|
| Hero | "The AI thinks. MUSU acts." | 그래서 내가 뭘 하는 건데? |
| Vampire | 기존 도구 설정 1초 흡수 | 흡수된 다음 화면에 뭐가 뜨는데? |
| P15 Engine | Holodeck, Chunking, Time Stone | 내가 이걸 설정하나? 자동인가? 어디서 보이나? |
| Warden | AI 행동 차단 | 차단되면 내 화면에 뭐가 뜨는데? |
| Zero Data Leak | 데이터 안 나감 | 내가 뭘 확인하는 건데? |
| HiveLink | 멀티 디바이스 연결 | 어떻게 연결하는데? 앱이 있나? |

**공통 문제: 기능 설명은 있지만 사용자 경험(시나리오)이 없다.**

---

## 필요한 시나리오: "설치 → 일상 → 사건 → 결과"

### 시나리오 1: 첫 설치

```
1. MUSU 깐다 (.exe 더블클릭)
2. "Cursor 발견, MCP 서버 4개 발견" 팝업 뜬다
3. [Import All] 버튼 한 번 누른다
4. 끝. 평소처럼 코딩한다.
```

### 시나리오 2: AI가 사고 치려는 순간

```
1. 평소처럼 Cursor로 코딩 중
2. AI가 rm -rf / 치려고 한다
3. 🔴 MUSU 알림: "위험 명령 차단됨 [PRV-010]"
4. 상세 보기 누르면: "AI가 루트 디렉토리 삭제를 시도했습니다. 즉시 차단."
5. 감사 로그에 기록됨
```

### 시나리오 3: 외출 중 원격 승인

```
1. 카페에서 노트북으로 코딩 중
2. AI가 프로덕션 DB 마이그레이션을 요청
3. 📱 폰에 푸시: "AI가 DB 스키마를 변경하려 합니다. 허락할까요?"
4. [Approve] 또는 [Reject] 탭
5. 승인하면 집 데스크탑(4090)에서 실행됨
```

### 시나리오 4: 월말 청구서

```
1. 평소처럼 코딩 (바뀐 거 없음)
2. 월말에 API 요금 확인
3. 지난달 $400 → 이번 달 $45
4. MUSU 대시보드: "Holodeck이 토큰 89% 절감"
```

## 구현 방향

### 옵션 A: 기존 섹션에 시나리오 삽입

각 기능 섹션(Warden, P15, HiveLink) 밑에 "실제로는 이렇게 보입니다" UI 목업 추가.
장점: 기존 구조 유지. 단점: 흐름이 분산됨.

### 옵션 B: 시나리오 전용 섹션 추가

"What it looks like" 섹션을 하나 만들어서 4단계 시나리오를 시각적으로 보여줌.
장점: 한눈에 사용 흐름 파악. 단점: 페이지가 더 길어짐.

### 옵션 C: 기존 섹션을 시나리오 중심으로 재작성

기능 설명 → 시나리오 + 기능 설명. 근본적 리라이트.
장점: 가장 효과적. 단점: 작업량 큼.

## VibePM 분석 원본

VibePM이 정리한 경쟁 지형도 해석:

### 4층 레이어 구조

```
┌─────────────────────────────────────────────────────┐
│                    사용자 (You)                       │
├─────────────────────────────────────────────────────┤
│  AI Agents    │  AI IDEs     │  AI CLIs    │  AI Platforms │
│  OpenClaw     │  Cursor      │  Claude Code│  bolt.new     │
│  Devin        │  Windsurf    │  Codex CLI  │  Replit Agent │
│  OpenDevin    │  Cline       │  Aider      │  v0           │
├─────────────────────────────────────────────────────┤
│                    ★ MUSU OS ★                      │
│         통제 · 보안 · 토큰 최적화 · 멀티디바이스        │
├─────────────────────────────────────────────────────┤
│              LLM (Claude, Gemini, GPT, DeepSeek)     │
└─────────────────────────────────────────────────────┘
```

### 층별 해석

- **1층 (사용자)**: 어떤 AI 툴을 쓰든 사용자의 자유
- **2층 (AI 도구들)**: Cursor, Claude Code, OpenClaw — "이 코드를 고칠까요?"라고 **제안(Propose)**하는 역할
- **3층 (MUSU OS)**: 모든 AI 도구의 밑바닥. AI의 제안이 실제 시스템에 닿기 전 검증/통제
- **4층 (LLM)**: Gemini, Claude, GPT가 지능이라는 전기를 공급

### 카테고리별 MUSU의 역할

| 카테고리 | 대표 주자 | 걔네가 하는 짓 | MUSU가 하는 짓 |
|----------|-----------|---------------|---------------|
| AI Agents | OpenClaw, Devin | AI 비서가 직접 행동 | 권한은 주되 행동은 검증 (Warden) |
| AI IDEs | Cursor, Windsurf | VS Code 포크해서 코딩 보조 | 설정 흡수 + 토큰 절감 |
| AI CLIs | Claude Code, Aider | 터미널에서 파일 수정/명령 실행 | 셸 인젝션 차단, 위험 명령어 컷 |

### 핵심 인사이트

- AI 도구들이 더 강력해질수록 → 사고 가능성 커짐 → 통제 수요 증가 → MUSU 필요성 증가
- 경쟁이 아니라 공생. 걔네가 성장하면 우리도 성장.
- MUSU의 진짜 경쟁자는 AI 도구들이 아니라 OS 벤더(Apple/Microsoft)가 네이티브로 AI 통제를 넣는 시나리오.
