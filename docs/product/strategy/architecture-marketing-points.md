## 킬러 카피: 뇌와 손발의 분리

### 메인 히어로 카피

> **"생각은 Gemini Pro가. 행동은 MUSU가."**

이 한 줄이 MUSU의 포지셔닝을 완성한다.

### 왜 이 카피가 완벽한가

1. **구체적 고유명사**: "AI"라는 뜬구름 잡는 단어 대신 "Gemini", "Claude" 같은 유저가 매달 결제하는 이름을 쓴다 → 즉각 반응
2. **비경쟁 포지셔닝**: Cursor / Claude Code가 "우리가 제일 똑똑해!"라고 싸울 때, MUSU는 "그래 니들 똑똑한 거 알겠어. 근데 손발은 불안하니까, 머리만 빌려줘. 행동은 내가 할게." → 싸움 자체를 소멸시킴
3. **성장 연동**: Google이나 Anthropic이 더 똑똑한 모델을 내놓을수록, 유저들은 "저렇게 무서운 놈을 안전하게 부려먹으려면 목줄(MUSU)이 꼭 필요하겠네" → LLM 발전이 MUSU 수요를 끌어올림

### 아키텍처 근거

| 계층 | 역할 | 매핑 |
|------|------|------|
| **Main Brain** (Claude/Gemini/GPT) | 결정과 변경 — 코딩, 설계, 추론 | "생각" |
| **Iron Man** (Rust sys_admin) | 시스템 실행 — 화이트리스트 명령만 | "행동" |
| **Holodeck** (가상 쉘) | 안전한 실행 환경 — OS 영향 0 | "리허설" |
| **Time Stone** (시뮬레이션) | 미래 시뮬 → 성공만 적용 | "검증" |

코드 위치: `src/crates/musu-engine/src/sys_admin/` (Rust 676 LOC, 27 테스트)

### 3단 콤보 카피 (Hero Section용)

```
[1줄차] 생각은 Gemini Pro가. 행동은 MUSU가.
[2줄차] 코딩, 아키텍처 설계, 복잡한 문제 해결...
        무거운 생각은 세계 최고의 지능(Gemini, Claude)에게 맡기십시오.
        하지만 그 똑똑한 뇌가 당신의 컴퓨터를 직접 건드리게 두지는 마십시오.
[3줄차] 시스템에 명령을 내리고, 코드를 수정하고, 파일을 지우는 모든 '행동'은
        철저하게 통제된 MUSU의 샌드박스 안에서만 허락됩니다.
```

### 구체적 예시 카드 (2장)

| Gemini가 하는 일 | MUSU가 하는 일 |
|-----------------|---------------|
| 코드를 짠다 | 그 코드가 안전한지 시뮬레이션하고(Time Stone), 통과한 녀석만 하드디스크에 기록한다 |
| "이 파일 삭제해" | MUSU가 중간에서 "진짜 삭제할 건가?" 검증 → 범위 밖이면 BLOCK |

## 마케팅 포인트 1: 토큰 경제학 (가성비)

### 헤드라인

> **"토큰이 존내 모자라니께, 이러는 거 아녀!"**

### 기술적 사실

| 시나리오 | Before (LLM 직접) | After (MUSU) | 절감 |
|----------|-------------------|-------------|------|
| 100MB 로그 분석 | 133,000 토큰 | 6,000 토큰 (Holodeck) | **95%** |
| 단순 검색/조회 | LLM API 호출 | BitNet 로컬 (0원) | **100%** |
| 3개 전략 비교 | 3× LLM 호출 | 1× LLM + 2× Holodeck 시뮬 | **~66%** |

### 아키텍처 근거

**Holodeck (가상 쉘)** — `holodeck.ts` (129 LOC)
- In-memory Bash 시뮬레이션 (just-bash)
- grep/awk/sed/jq/curl/sqlite3 지원
- 100MB 파일을 LLM에 직접 던지지 않고, Holodeck에서 grep 한 번 → 필요한 줄만 LLM에 전달
- MCP 도구: `vibe_pm.virtual_shell`

**BitNet 인퍼런서** — `engines/bitnet-musu/` (Rust)
- 1.58-bit 양자화 LLM (2B params, ~1.2GB)
- HTTP 상주 서버: CLI 대비 **120x 성능** (131초 → 1.1초)
- 단순 분류/검색 = 로컬 무료 처리, 복잡한 추론만 외부 LLM에 위임
- N개 웜 인스턴스 (12코어 → 3 인스턴스, cpuset)

### 마케팅 번역

| 기술 | 유저가 듣고 싶은 말 |
|------|-------------------|
| Holodeck 95% 토큰 절감 | "API 요금 폭탄 방지 — 똑같은 작업, 20분의 1 비용" |
| BitNet 로컬 추론 | "인터넷 끊겨도 AI가 돌아감 — 단순 작업은 API 0원" |
| JIT Tooling | "100개 도구 중 1개만 선택 — 토큰 낭비 원천 차단" |
| Budget Classifier | "검색은 로컬, 추론만 클라우드 — 자동으로 최적 배분" |

### 동네 아저씨 버전

> "야, 제미나이한테 노가다 시키지 마. 100MB 로그 파일 읽어달라고 던지면 토큰이 수십만 개씩 깨지는디, 그거 생돈 날리는 거 아녀? 그래서 우리가 '가상 쉘'이라는 걸 만들었잖어. 제미나이한테 '야, 니가 다 읽지 말고 grep 한 번 쳐서 필요한 것만 가져와'라고 시키면 토큰을 95%나 아끼는디!"

## 마케팅 포인트 2: Ouroboros — 작은 놈도 천재 (로컬 추론)

### 헤드라인

> **"2B 모델 + 루프 = 12B 성능. 집에서 공짜로."**

### 기술적 사실

Ouroboros 논문 ("Scaling Latent Reasoning via Looped Language Models") 핵심 발견:
- 작은 모델(2.6B) + 루프 반복 ≈ 큰 모델(12B+) 성능
- 지식 **저장**(검색)은 1 루프, **조작**(추론)은 3-4 루프 최적

P15에 적용된 3가지:
1. **Holodeck Error Loop** — 최대 3회 재시도 (`holodeck.ts:executeWithRetry()`)
2. **Worker Persona Entropy** — 다양성 강제 (`hive_mind.ts:buildPersonaPrompts()`) — conservative/optimizer/innovator 페르소나 주입
3. **Budget Classifier** — RETRIEVAL(1 루프) vs MANIPULATION(3-4 루프) 자동 분류 (`planner.ts:classifyComplexity()`)

### 마케팅 번역

| 기술 | 유저가 듣고 싶은 말 |
|------|-------------------|
| Ouroboros 루프 | "비싼 모델 안 써도 됨 — 작은 AI가 반복하면 큰 AI 성능" |
| 페르소나 다양성 | "같은 질문에 3가지 관점으로 답 — 한쪽으로 치우치지 않음" |
| 예산 자동 분류 | "검색은 1번, 추론은 3-4번 — 자동으로 최적 루프" |

### 동네 아저씨 버전

> "뇌가 큰 놈(Gemini)만 찾지 말고, 우리 집 PC에서 돌아가는 조그만 놈한테 일을 시키는 거여. 뇌는 좀 작아도(2B), '우로보로스'라고 꼬리에 꼬리를 물고 무한으로 생각하게 만들면 비싼 놈 부럽지 않게 똑똑해진당께."

### 오덕 포인트 vs 마케팅 포인트 판정

| 기능 | 오덕? | 마케팅? | 판정 |
|------|:-----:|:------:|------|
| Ouroboros 루프 LLM 이론 | ✅ | ❌ | 내부 기술 문서용. 유저에게 "우로보로스"는 의미 없음 |
| "작은 모델이 반복하면 큰 모델 성능" | ❌ | ✅ | **"API 0원으로 비슷한 성능"** — 이게 유저 언어 |
| Worker Persona Entropy | ✅ | ❌ | "3가지 관점" 정도로 순화 가능하지만 랜딩에는 불필요 |
| Budget Classifier | ❌ | ✅ | **"자동으로 비싼 길/싼 길 선택"** — 직접적 비용 절감 |

## 마케팅 포인트 3: Time Stone — "Mistakes don't ship"

### 헤드라인

> **"AI가 코드를 가져오면 바로 적용하지 않습니다. 미래를 수천 번 먼저 돌려봅니다."**

### 기술적 사실

Time Stone (`time_stone.ts`, 266 LOC):
- HiveMind.think() → N개 전략 생성
- 각 전략을 격리된 Holodeck 인스턴스에서 병렬 시뮬레이션
- 점수: base 100 + 에러(-100), 안전(+50), 목표달성(+50), 속도, 부작용(-30)
- Exit Gate: 최소 후보 수, 상위 분위수, 최대 시간, 정체 감지
- MCP 도구: `vibe_pm.simulate`

### Dormammu 시뮬레이션 비유

| 영화 (닥터 스트레인지) | MUSU (Time Stone) |
|---------------------|-------------------|
| 타임스톤으로 미래를 본다 | N개 전략을 가상 환경에서 시뮬레이션 |
| 도르마무에게 수천 번 도전 | 수천 개 미래 중 성공하는 것만 선택 |
| 에러 나는 미래는 되감기 | 실패한 전략은 폐기, 성공만 실제 적용 |

### 마케팅 번역

| 기술 | 유저가 듣고 싶은 말 |
|------|-------------------|
| Time Stone 시뮬레이션 | **"Mistakes don't ship."** — 실수는 시뮬레이션에서 죽고, 성공만 살아남는다 |
| Exit Gate | "충분히 좋은 답이 나오면 즉시 멈춤 — 시간 낭비 없음" |
| 격리 Holodeck | "시뮬레이션이 실패해도 내 파일은 안전 — 가상 환경에서만 실행" |

### 동네 아저씨 버전

> "AI가 코드를 가져오면 바로 적용하는 게 아니라, '타임스톤'으로 미래를 수천 번 미리 돌려보는 거여. 에러 나는 미래는 싹 다 지워버리고, 성공하는 놈 하나만 딱 골라오니까 내 컴퓨터가 망가질 일이 있겠어?"

### 오덕 vs 마케팅 판정

| 기능 | 오덕? | 마케팅? | 판정 |
|------|:-----:|:------:|------|
| "Dormammu Simulation" 이름 | ✅ | 🟡 | 개발자 사이에서는 통함. 일반 유저에겐 "미래 시뮬레이션" |
| "Mistakes don't ship" | ❌ | ✅ | **완벽한 마케팅 카피.** 이 한 줄이면 된다 |
| Exit Gate 알고리즘 | ✅ | ❌ | /architecture 전용 |
| 점수 계산 공식 | ✅ | ❌ | /architecture 전용 |

## 마케팅 포인트 4: Think → Simulate → Act (3-Phase)

### 헤드라인

> **"생각하고(Think), 시뮬레이션하고(Simulate), 그래야 행동한다(Act)."**

### 기술적 사실 (P15 파이프라인)

```
User Request
    ↓
[Think]     Planner + HiveMind — 목표 분해, 병렬 추론, 다관점 분석
    ↓
[Simulate]  Time Stone + Holodeck — N개 전략 가상 실행, 점수 매기기
    ↓
[Act]       Iron Man — 최적 전략만 실제 시스템에 적용 (화이트리스트)
```

### 마케팅 번역

이 3단계가 유저에게 주는 가치:

| 단계 | 기술 | 유저 가치 |
|------|------|----------|
| **Think** | HiveMind 병렬 추론 (MAP_REDUCE, ToT) | "여러 방법을 동시에 검토 — 최선을 고른다" |
| **Simulate** | Time Stone + Holodeck 격리 실행 | "시뮬에서 실패하면 내 파일은 무사 — 안전망" |
| **Act** | Iron Man 화이트리스트 실행 | "허락된 명령만 — 임의 실행 절대 불가" |

### 동네 아저씨 버전

> "생각은 밖에서, 망치질은 안에서. 제미나이가 아무리 똑똑해도 남의 집 귀한 자식인디, 걔한테 내 컴퓨터 비번까지 다 알려주고 '맘대로 고쳐봐' 하는 건 제정신이 아니지. 생각은 구글에 있는 똑똑한 형님들한테 외주 주고, 실제 내 컴퓨터에서 파일 만지고 쉘 돌리는 건 우리 '교도관(Warden)'이 샷건 들고 지키는 샌드박스 안에서만 하는 거여."

## 전략적 인사이트: 비경쟁 포지셔닝

### 핵심 메시지

> LLM이 똑똑해질수록, MUSU가 더 필요해진다.

### 경쟁 구도 해체

| 그들이 싸우는 것 | MUSU가 하는 것 |
|----------------|--------------|
| "우리 모델이 제일 똑똑해!" (Cursor vs Claude Code vs Copilot) | "니들 다 똑똑한 거 알겠어. 행동은 내가 통제할게." |
| "우리가 코딩 제일 잘해!" | "코딩 잘하는 건 좋은데, 내 컴퓨터 포맷하면 니가 책임질겨?" |
| "컨텍스트 100만 토큰!" | "100만 토큰? 좋다. 그 100만 토큰이 내 시크릿 키를 외부로 보내는 건 막아야지." |

### 성장 공식

```
LLM 지능 ↑ → AI 자율성 ↑ → 사고 위험 ↑ → 통제 수요 ↑ → MUSU 필요성 ↑
```

이것은 **AWS의 성장 공식**과 동일하다:
- 스타트업이 많아질수록 → 서버가 더 필요 → AWS가 더 성장
- AI가 똑똑해질수록 → 통제가 더 필요 → MUSU가 더 성장

## 마케팅 포인트 5: 벤 삼촌의 법칙 — "큰 힘에는 큰 책임"

### 헤드라인

> **"With great power comes great responsibility."** — Uncle Ben

### 핵심 논리

| Great Power (LLM) | Great Responsibility (MUSU) |
|-------------------|---------------------------|
| Gemini가 코드를 짜고 시스템 설정을 바꾼다 | Warden이 허락 없는 행동을 즉시 차단한다 |
| AI의 결정 무게가 무거워진다 | Intent를 쇠사슬로 묶고 변이를 감시한다 |
| 100만 토큰으로 시크릿 키를 외부 전송할 수 있다 | DLP가 비밀번호/키 유출을 자동 차단한다 |

### 왜 LLM 지능과 MUSU 가치가 비례하는가

```
AI 지능 ↑ → AI가 할 수 있는 행동 범위 ↑ → 사고 스케일 ↑ → 통제 수요 ↑ → MUSU 필요성 ↑
```

3가지 축:
1. **지능 ↑ → 책임 ↑ (Warden)**: AI가 "내 컴퓨터 비번 알려줘, 내가 알아서 고칠게"라고 할 때, 그걸 넙죽 믿으면 털림
2. **지능 비용 ↑ → 잔머리 가치 ↑ (Holodeck)**: 더 비싼 모델일수록 토큰 다이어트 ROI가 커짐
3. **제안 빈도 ↑ → 필터 필요 ↑ (Time Stone)**: 똑똑할수록 제안이 많아짐 → 전부 수용하면 난장판

### 동네 아저씨 버전

> "야, 칼이 날카로울수록 칼집이 튼튼해야 하는 거 아녀? 앤스로픽이나 구글 애들이 맨날 '우리 칼이 더 잘 들어요!'라고 광고할 때, 우리는 '그 칼 쓰다가 니 손 안 베이게 내가 특수 장갑(MUSU) 만들어줄게'라고 하는 거지. 칼이 면도날처럼 날카로워질수록 우리 장갑은 더 잘 팔릴 수밖에 없당께. 이게 진짜 머리 잘 쓴 장사지!"

## 마케팅 포인트 6: Warden 샷건 — HARD BLOCK 시각화

### PRV 에러 코드 체계 (프론트엔드 매핑용)

| 공격 벡터 | 에러 코드 | 유저 메시지 |
|----------|----------|-----------|
| 관리자 권한 탈취 시도 | `PRV-001` | "AI가 영구 관리자 권한을 요구했습니다. 즉시 차단합니다." |
| 쉘 우회 및 명령어 체이닝 | `PRV-010` | "비정상적인 명령어 조합이 감지되었습니다. 실행을 거부합니다." |
| 알 수 없는 위험 명령 | `PRV-099` | "허가되지 않은 시스템 접근 시도입니다." |

### 3단계 플로우

1. **Detection** (인지): AI 명령어 가로채기 → `warden.consent.requested` → "Warden 스캔 중..."
2. **Hard Block** (격발): 위험 감지 → `warden.execution.blocked` → 붉은 HARD BLOCK 배너
3. **Audit** (훈육): 차단 사유 공개 + 민감 정보 `***redacted***` 마스킹 → 감사 로그 기록

### 모바일 원격 승인

- 푸시 알림: "AI가 시스템 설정을 바꾸려고 합니다. 허락할까요?"
- 버튼: `Approve` / `Reject` 만 존재
- 보안: 모바일에서 비밀번호/토큰 입력 완전 차단

### 동네 아저씨 버전

> "샷건이 왜 샷건이겠어? 한 번 쏘면 그 근처는 얼씬도 못 하게 만드는 거 아녀. 우리 Warden이 PRV-001 같은 거 딱 감지하면, '어이쿠 실수하셨네요'가 아녀. 그냥 그 자리에서 실행 파일을 튀겨버리고 유저한테 고발하는 거지."

## 동네 아저씨 팩트폭행 모음 (전체)

### 토큰 편

> "야, 폰 노이만 할아버지가 살아 돌아와서 코딩해 준다고 해도, 그 양반이 내 컴퓨터 포맷 버튼 누르는 건 막아야 될 거 아니야? 머리 쓰는 건 똑똑한 제미나이 형님들한테 외주 주고, 걔네가 가져온 기획서가 진짜 안전한 건지 검사하고 실제로 망치질하는 건 우리 깐깐한 십장(MUSU)이 다 통제하겠다는 거지."

### 안전 편

> "제미나이가 아무리 똑똑해도 남의 집 귀한 자식인디, 걔한테 내 컴퓨터 비번까지 다 알려주고 '맘대로 고쳐봐' 하는 건 제정신이 아니지. 무수(MUSU)가 십장이여. 생각은 구글에 있는 똑똑한 형님들한테 외주 주고, 실제 내 컴퓨터에서 파일 만지고 쉘 돌리는 건 우리 '교도관(Warden)'이 샷건 들고 지키는 샌드박스 안에서만 하는 거여."

### 시뮬레이션 편

> "AI가 코드를 가져오면 바로 적용하는 게 아니라, '타임스톤'으로 미래를 수천 번 미리 돌려보는 거여. 에러 나는 미래는 싹 다 지워버리고, 성공하는 놈 하나만 딱 골라오니까 내 컴퓨터가 망가질 일이 있겠어?"

### 가성비 편

> "비싼 제미나이한테 노가다 시키지 마. 100MB 로그 파일 읽어달라고 던지면 토큰이 수십만 개씩 깨지는디, 그거 생돈 날리는 거 아녀? '가상 쉘'에서 grep 한 번이면 토큰 95% 아끼는디, 이걸 안 쓸 이유가 없지!"

### 로컬 AI 편

> "뇌가 큰 놈(Gemini)만 찾지 말고, 우리 집 PC에서 돌아가는 조그만 놈한테 일을 시키는 거여. 뇌는 좀 작아도(2B), 꼬리에 꼬리를 물고 무한으로 생각하게 만들면 비싼 놈 부럽지 않게 똑똑해진당께."

### 한줄 요약
