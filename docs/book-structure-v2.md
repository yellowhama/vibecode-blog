# AI 통제 이론 — 책 구조 v2

> v1에서 변경: 기존 블로그 글 재배치 → **신규 집필 중심, 기존 글은 소스/베이스**
> 각 챕터 목표 분량: **10,000-15,000자** (기존 평균 3,600자 → 3-4배 확장)

---

## 정체성

**제목 후보:**
1. **짜증이 스펙이다** — AI 시대, 코딩 모르는 사람의 통제 전략
2. **통제의 기술** — 바이브코더를 위한 AI 설계 가이드
3. **AI는 정답을 안 준다** — 경계선을 줄 뿐이다

**독자:** 코딩을 모르지만 AI로 뭔가 만들고 싶은 사람. 만들다가 매번 망하는 사람.

**약속:** 이 책을 읽고 나면 AI에게 시키고, 잡고, 찾게 하고, 걸러낼 수 있다.

**톤:** 부코우스키 60% + Indie Hacker 30% + Product 10% (docs/translation-guide.md 준수)

**분량 목표:** ~200,000자 (A5 기준 약 350-400페이지)

## 구조 개요

```
선언문: 바이브코딩은 죽었다. 통제가 시작됐다.
  ↓
1부: 통제 상실 — "왜 망하는가" (3장)
  ↓
2부: 통제 ① 결정 — "뭘 만들 것인가" (3장)
  ↓
3부: 통제 ② 구조 — "어떻게 고정할 것인가" (3장)
  ↓
4부: 통제 ③ 검색 — "어떻게 찾을 것인가" (3장)
  ↓
5부: 통제 ④ 신뢰 — "뭘 믿을 것인가" (3장)
  ↓
6부: 종합 — "짜증에서 제품까지" (2장)
  ↓
부록 (2장)
```

총 **20장** (선언문 + 15장 본문 + 2장 종합 + 2장 부록)

#### Ch.1 — 따라했는데 왜 망하죠?

**분량:** 12,000자
**소스:** 049 (바이브코딩 실패), 008 (게임 만들기 30시간)
**새로 추가할 내용:**

```
1. 튜토리얼의 함정
   - 강의 따라하면 되는 줄 알았다
   - [소스 049] 실패 경험 확장 — 구체적 에러 로그, 시간 기록
   - 새 사례: 다른 바이브코더들의 실패 패턴 3가지
     · "AI가 다 해줄 줄 알았어요" (과신)
     · "되다가 갑자기 안 돼요" (누적 오류)
     · "뭐가 잘못된 건지 모르겠어요" (진단 불능)

2. AI의 "잘 돼요" 함정
   - 간단한 건 진짜 잘 된다 → 자신감 부풀림
   - 복잡도 임계점: ~500줄에서 무너지기 시작
   - [새 콘텐츠] 복잡도-오류 곡선 그래프 + 설명
   - "AI는 0→1이 아니라 0→0.6을 해준다. 나머지 0.4가 지옥."

3. 진짜 문제: 결정의 누적
   - [소스 050] "코딩이 아니라 결정" 논지 확장
   - 결정은 보이지 않게 쌓인다 — 파일 구조, 변수명, 아키텍처
   - AI가 대신 내린 결정 100개 = 내가 이해 못하는 코드 100줄
   - "결정을 안 하면 AI가 대신 한다. AI의 결정은 무작위다."

4. 진단: "당신은 통제를 잃었다"
   - 통제 상실의 3단계: 자신감 → 혼란 → 포기
   - "에러가 문제가 아니다. 에러를 이해할 수 없는 게 문제다."
```
