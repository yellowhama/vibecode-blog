# 019 클러드코드 스킬

# **AI 바이브 코딩 에이전트 3대장 비교와 실전 워크플로우**

### Claude Code vs Codex vs Gemini CLI 비교와 워크플로우

---

## **AI 코딩 도구의 세대 교체 – 세 개의 터미널, 세 개의 성격**

Claude Max를 쓰다가 처음으로 “한도 초과”라는 문구를 봤다.

하루 종일 명세를 쓰고, 리팩토링하고, 테스트를 돌리다 보니

잔고가 사라졌다.

그래서 50달러를 충전했다.

그런데 반나절도 안 돼서 증발했다.

이때부터 내 삶은 복잡해졌다.

GPT를 유료 결제하고 Codex CLI를 깔았다.

며칠 뒤에는 Gemini CLI까지 설치했다.

구글 클라우드는 이미 결제 중이었으니까.

그렇게 두 대의 컴퓨터에서

Claude, Codex, Gemini — 세 개의 터미널이 동시에 켜지게 됐다.

세 도구는 같은 일을 하지만, 완전히 다른 태도로 일했다.

---

## **Codex CLI – 코드 정확도 1위, GitHub 기반 AI 프로그래머**

Codex는 코드를 짜는 속도가 미쳤다.

Rust, TypeScript, Python을 섞어 써도 망설임이 없다.

명령을 주면 정확히 그 줄만 바꾼다.

한 줄이 틀리면 즉시 알려주고, 테스트를 돌리고, 커밋까지 남긴다.

어느 순간 깨달았다.

Codex가 이렇게 정확한 이유는 구조 자체가 다르기 때문이다.

**이 도구는 GitHub 리포지토리를 기준으로 생각한다.**

코드를 직접 “생성”하는 게 아니라,

파일의 스냅샷을 읽고 diff 단위로 판단한다.

버전, 경로, 커밋 이력—all 그 문맥 위에서 움직인다.

그래서 “코드를 고쳐라”라는 말 대신

“이 커밋 이후 변경된 로직만 수정해줘”라고 해야 더 잘 이해한다.

Codex는 대화형 모델이 아니라 **버전 기반 프로그래머**다.

손은 빠르지만, 상상력은 없다.

정해진 규칙 안에서는 완벽하게 일하지만,

새로운 아이디어에는 약하다.

그래서 나는 구조를 Claude에게 맡긴다.

---

## **Claude Code – 명세서·문서 자동화에 최적화된 AI 워크플로우 도구**

Claude는 코드를 짜기보단 시스템을 이해한다.

PROJECT_CONTEXT.md를 던지면

디렉토리 구조와 의존성을 읽어내고,

Spec, Plan, Tasks를 나눠 정리한다.

이건 단순한 정리 기능이 아니다.

**Claude Code는 Skills + Context라는 두 계층 구조를 가진다.**

Skills는 “작업 단위”다.

spec-analyzer, game-dev-lead, status-tracker 같은 것들.

명세를 분석하고, 상태를 점검하고, 작업을 분해한다.

Context는 “기억”이다.

프로젝트 규칙, 디렉토리, 시스템 계층 구조를 담은 문서들.

Claude는 이걸 읽고 대화한다.

그래서 이전 대화가 끊겨도 흐름이 이어진다.

다른 도구들은 명령을 받고 끝나지만,

Claude는 다음 단계를 제안한다.

“이 기능은 Phase 2입니다. Plan 파일을 먼저 쓰죠.”

이런 식이다.

즉, Claude는 **명령형 도구가 아니라 구조적 사고 도구**다.

속도는 느리지만, 방향이 틀리지 않는다.

문서를 쓰고 명세를 다듬을 때 Claude만한 AI가 없다.

---

## **Gemini CLI – 데이터 정리·ELT·PDF 텍스트화에 강한 Google AI 에이전트**

Gemini는 완전히 다른 영역이다.

코드를 짜는 대신, **데이터를 정리한다.**

논문 PDF를 넣으면 10초 만에 Markdown으로 바꿔준다.

표를 던지면 SQL 스크립트로 바꾸고,

ELT 자동화 파이프라인도 짜준다.

나는 Gemini로 PDF 텍스트 변환용 Python 스크립트를 만들었다.

또 개인 데이터 위키를 만들 때는

SQL + ELT 기반으로 자료를 정리하는 데 썼다.

매일 밤 자동으로 갱신되는 위키.

이건 Gemini 아니면 못 한다.

이게 가능한 이유는 단 하나, **대화형 셸(PTY)**.

Gemini CLI는 실제 터미널처럼 vim, top, git rebase -i 같은

복잡한 명령도 처리할 수 있다.

즉, “정리”라는 개념을 코드와 터미널 수준으로 끌어올린다.

Claude가 설계를, Codex가 코드를,

Gemini가 문서와 데이터를 맡는 셈이다.

---

## **AI 코딩 생산성 3배 – 세 도구를 함께 쓸 때 생기는 워크플로우**

지금 내 구조는 이렇다.

- **Codex** — 코드 작성과 수정
- **Claude** — 명세, 구조, 문서 관리
- **Gemini** — 자료 정리, 데이터 파이프라인, 자동화

Claude가 만든 Plan을 Codex에게 넘기면,

Codex가 코드를 완성하고 테스트까지 돌린다.

그 결과물을 Gemini가 PDF나 Wiki 형태로 정리한다.

하루가 끝나면 폴더가 깨끗하게 정리돼 있다.

STATUS.md, CHANGELOG.md, ERD, SQL 문서—all 자동.

예전엔 “하루 종일 코딩했는데 뭐가 바뀌었는지 모르겠다”였다면,

이제는 “하루가 끝나면 보고서가 정리돼 있다”가 됐다.

AI가 일을 나눠 맡는다.

나는 구조를 설계하고, 이들은 각자 맡은 일을 한다.

---

## **왜 Codex·Claude·Gemini가 각자 다른가 – 구조적 차이 분석**

결국 원인은 구조에 있다.

Codex는 GitHub라는 확실한 기준점이 있다.

커밋 단위로 세상을 본다.

그래서 **코드 정확도가 가장 높다.**

Claude는 자체 컨텍스트 시스템을 갖고 있다.

Skills와 Context를 엮어서,

프로젝트의 전체 그림을 유지한다.

그래서 **명세와 문서의 일관성이 가장 높다.**

Gemini는 PTY 기반의 인터랙티브 셸을 갖고 있다.

터미널 자체를 시뮬레이션하면서

파일을 읽고 변환하고 구조화한다.

그래서 **데이터와 문서 정리 효율이 가장 높다.**

즉, 이건 단순한 ‘성능 차이’가 아니라

**설계 철학의 차이**다.

Codex는 엔진, Claude는 시스템, Gemini는 인터페이스다.

---

## **AI 개발의 미래 – 선택이 아니라 배치의 시대**

예전엔 “어떤 AI가 더 좋을까”를 고민했다.

이제는 “어떤 AI에게 어떤 일을 맡길까”를 고민한다.

Codex는 손, Claude는 머리, Gemini는 눈이다.

세 개가 동시에 돌아가면

AI는 하나의 팀처럼 움직인다.

Claude가 설계하고,

Codex가 실행하고,

Gemini가 정리한다.

나는 그 위에서 시스템을 설계한다.

코드를 덜 짜고, 일을 더 설계한다.

**도구의 시대는 끝났다.**

**이제는 AI 코딩 에이전트 ‘배치’의 시대다.**

---

**TL;DR**

- Claude Max 한도 초과로 Codex·Gemini CLI까지 도입 → 세 개의 AI를 병행 사용.
- **Codex CLI**: GitHub 기반 diff 구조 덕분에 코드 정확도·속도 최고.
- **Claude Code**: Skills+Context 구조로 명세·문서·워크플로우 관리에 최적.
- **Gemini CLI**: PTY 셸 지원으로 데이터 정리·ELT·PDF 변환에 강함.
- 세 도구를 조합하면 “코드는 Codex, 문서는 Claude, 정리는 Gemini” 체계가 완성된다.
- AI를 ‘선택’하는 시대는 끝났고, 이제는 **역할을 배치하는 시대**다.
