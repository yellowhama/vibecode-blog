# Claude Code 제대로 쓰는 법 01: **설명서를 AI에게 읽게 하라**

**AI 코딩 툴의 진짜 활용법 | 블로그 팁보다 강력한 “AI 자기학습” 전략**

---

## TL;DR (요약)

- Claude Code를 배우지 말고, **Claude Code가 스스로 배우게 하라.**
- 블로그 팁은 ‘누군가의 경험’일 뿐이지만, Claude는 **제작사의 모든 문서**를 학습할 수 있다.
- Anthropic GitHub의 53개 리포지토리를 Claude에게 읽히면,
    
    당신의 프로젝트에 맞는 **맞춤형 AI 개발 환경**이 자동으로 구성된다.
    
- **핵심:** “설명서를 내가 읽는 대신, AI에게 읽히게 하라.”
    
    그것이 진짜 AI 시대의 개발 방식이다.
    

---

## AI 개발의 함정: **팁 모음집을 아무리 읽어도 내 프로젝트엔 안 맞는다**

당신은 아마 이런 글들을 봤을 것이다.

“Claude Code 활용 팁 10가지”, “Claude Code 마스터하기”, “실전 Claude Code 가이드”.

나도 읽었다. CLAUDE.md 작성법, 슬래시 커맨드 설정법, 훅 활용법.

모두 유용했다. 그런데 막상 적용하려 하면 어딘가 어긋났다.

그들의 예시는 React였지만 나는 Python이었다.

그들은 팀이었지만 나는 혼자였다.

결국 팁을 내 상황에 맞게 번역하는 게 또 다른 일이 됐다.

그래서 깨달았다. **나는 누군가의 경험을 따라 하고 있었던 것이다.**

여기 진짜 좋은 방법이있다.
세상에서 가장 클러드 코드를 잘 쓰는 방법이다.
단언컨대 이것보다 더 좋은 방법은 없다.

---

## AI 메타 학습의 출발점: **“원천으로 가라”**

Claude Code를 가장 잘 아는 사람은 누굴까?

유튜버도, 블로거도 아니다.

**Claude Code를 만든 사람들, 즉 Anthropic 팀**이다.

그들의 GitHub에는 53개의 리포지토리가 있다.

공식 문서, 실사용 예제, 수천 개의 토론, 100여 개의 MCP 서버까지.

하지만 나는 그걸 다 읽을 수 없다.

그런데 문득 이런 생각이 들었다.

> “Claude Code는 내 코드를 읽을 수 있는데,
> 
> 
> 그럼 자기 자신에 대한 문서도 읽을 수 있지 않을까?”
> 

---

## 실험 ①: **AI에게 자기 설명서를 읽히다**

```
"Anthropic GitHub 저장소의 claude-code 관련 자료를 전부 분석해줘.
무엇을 할 수 있고, 어떻게 설정하면 좋을지 정리해."

```

Claude는 30분 동안 문서와 이슈, 코드 샘플을 분석했다.

그리고 **스스로 자기 사용 매뉴얼을 만들어냈다.**

그건 단순한 요약이 아니었다.

CLI, Hooks, MCP, 서브에이전트 구조까지 —

블로그 어디에도 없던 내용이었다.

**AI가 자기 자신을 공부한 결과물**이었다.

---

## 실험 ②: **학습한 AI에게 내 프로젝트를 맡기다**

```
"좋아. 우리 프로젝트는 백엔드 API야.
데이터베이스 스키마 수정이 많고,
프로덕션 환경 파일은 절대 건드리면 안 돼.
이 상황에 맞게 설정을 짜줘."

```

Claude는 바로

- CLAUDE.md 구조화
- 자주 쓰는 작업을 슬래시 커맨드로 자동화
- 프로덕션 파일 보호용 훅 설치

까지 해냈다.

나는 “훅이 뭔지” 몰랐지만,

Claude는 공식 문서에 있던 **PreToolUse Hook**을 활용했다.

나는 “보호해달라”고만 말했을 뿐이다.

---

## 블로그 팁 vs 공식 문서: **정보의 밀도 차이**

일주일 후 대규모 리팩토링을 하게 됐다.

예전 같으면 “Claude Code 대규모 프로젝트 팁”을 검색했을 것이다.

이번엔 Claude에게 물었다.

```
"너 공식 문서에서 대규모 프로젝트 다루는 법 배웠지?
특히 컨텍스트 관리 쪽."

```

Claude는 **서브에이전트 시스템**을 제안했다.

전문 에이전트가 모듈 단위로 분석하고,

컴포넌트 인덱스 파일로 전체 구조를 시각화하는 방식.

**이건 어디에도 없던 방식**이었다.

왜냐하면 Claude는 블로그가 아니라,

**제작사의 설계 의도 전체**를 읽었기 때문이다.

---

## 진화하는 AI 개발 파트너: **실수도 학습시켜라**

어느 날 Claude가 중요한 설정 파일을 잘못 고쳤다.

나는 이렇게 말했다.

```
"이건 수정하면 안 되는 파일이야.
너 공식 문서에서 이런 실수 막는 방법 찾아서 적용해."

```

Claude는 **PreToolUse Hook**을 찾아냈다.

이제 그 파일은 자동으로 보호된다.

나는 “hook”이 뭔지 몰라도 된다.

**Claude가 스스로 찾아서 배웠다.**

---

## 도구를 배우지 말고, **AI가 배우게 하라**

우리는 늘 ‘사용법’을 배워왔다.

튜토리얼을 보고, 팁을 따라 하고, 오류를 수정하며 익혔다.

그런데 Claude Code는 다르다.

이건 도구가 아니라 **학습 가능한 시스템**이다.

당신이 해야 할 일은 단 하나.

> “설명서를 내가 읽는 대신, AI에게 읽히게 하라.”
> 

AI는 스스로 학습하고,

당신의 프로젝트 맥락에 맞게 재조합한다.

---

## 지금 바로 시작하기: **30분 안에 AI 자기학습 세팅**

1. Claude Code 실행
2. 입력:
    
    ```
    "Anthropic GitHub 전체를 분석해서
    claude-code 관련 자료를 정리해줘.
    그리고 네가 어떻게 작동하는지,
    뭘 할 수 있는지 요약해."
    
    ```
    
3. 기다린다 (30~60분)
4. 결과 파일: `CLAUDE_CODE_MASTER_GUIDE.md`

이제 블로그 검색은 끝이다.

무엇이든 Claude에게 묻기만 하면 된다.

“자동화할 수 있어?”, “대규모 관리법 알려줘?”,

“팀 전체 설정 공유하려면?”

Claude는 이미 답을 알고 있다.

**공식 문서에 있으니까.**

---

## 결론: **설명서를 읽는 사람이 아닌, 읽게 하는 사람이 되어라**

이상하게 들리겠지만,

이건 학습의 주체가 인간에서 AI로 바뀐 첫 번째 순간이었다.

> 우리는 더 이상 도구를 배우는 존재가 아니다.
> 
> 
> 이제 도구가 우리를 배운다.
> 

이게 Claude Code를 제대로 쓰는 첫 번째 방법이다.

그리고 아마도 가장 중요한 방법일 것이다.

왜냐하면 이 한 가지만 제대로 하면,

나머지는 Claude가 알아서 알려주기 때문이다.
