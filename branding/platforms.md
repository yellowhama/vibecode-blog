## 트윗 (X / @lazy_genius2025)

**톤**: Bukowski 80%. 가장 날것.

| 항목 | 규칙 |
|------|------|
| 길이 | 짧게. 280자 기본. Premium 긴 글도 OK. |
| 전면 | **행동**. 디테일(스펙/숫자)은 배경. `narrative.md` §3 참조. |
| 구조 | 페르마 구조. 첫 트윗 = 선언. 쓰레드 = 깊이. |
| 비속어 | OK (damn, hell, pissed) |
| 링크 | **절대 안 넣음**. 프로필 바이오에만. |
| CTA | 없음 |
| 마무리 | 결론 없어도 됨. 해결 못 했으면 못 한 채로 끝남. |
| 쓰레드 | 기본 형식. 첫 트윗이 독립적으로 성립 + 아래에 깊이. |
| 리플라이 | 진짜 할 말 있을 때만. 타겟팅 아님. |

**이 매체에서 가장 중요한 것:**
1. 행동이 전면, 디테일은 배경. 2. 한 트윗에 기승전결 넣지 않음.
3. 광고 카피 테스트. "이거 광고 같냐?" → `examples.md` 참조.

## 블로그 (vibecode.town)

**톤**: 모드 A 또는 B 선택. 내용에 따라.

| 항목 | 규칙 |
|------|------|
| 길이 | 자유 |
| 구조 | 모드 A면 생각 순서. 모드 B면 섹션 헤딩 있음. |
| 비속어 | OK |
| 링크 | 자연스러운 내부 링크 OK |
| 마무리 | 선언문 한 줄로 찍는다 |
| 코드 블록 | 실제 코드. 설명보다 코드가 먼저. |

**이 매체에서 가장 중요한 것:**
글 유형에 따라 톤 비율 조절.

| 글 유형 | Bukowski | Indie Hacker | Product |
|---------|----------|--------------|---------|
| 경험담/실패기 | **70%** | 20% | 10% |
| 도구 리뷰 | 30% | **50%** | 20% |
| AI 산업 비평 | **60%** | 10% | 30% |
| 기술 해설 | 20% | 30% | **50%** |
| 방법론 | 30% | **50%** | 20% |

## 뉴스레터 (Beehiiv)

**톤**: Bukowski 60%. 살짝 정돈되지만 여전히 구어체.

| 항목 | 규칙 |
|------|------|
| 길이 | 중간. 5분 이내 읽기. |
| 구조 | 간단한 구조 OK. 번호 리스트 OK. |
| 비속어 | 약간 조절 (hell OK, damn OK) |
| 링크 | 블로그 링크 하나 OK. 자연스럽게. |
| CTA | 하나. 끝에. |
| 마무리 | 다음 주 예고 or 짧은 선언 |

**이 매체에서 가장 중요한 것:**
매주 보내는 거니까 "친구한테 보내는 근황" 톤.
보고서가 아님. 편지도 아님. 그냥 "이번 주 이랬다."
