# "AI, You Write All the Code" -- The Vibe Coding Era Is Here

## AI writes the code now. So what do developers do?

"Vibe Coding." That's the term going around.

Vibe as in feeling. Mood. So you code by... vibes?

**Andrej Karpathy coined it. February 2025.** OpenAI co-founder. Former Tesla AI lead. You describe what you want in plain words. The LLM writes the code. You review and tweak. Karpathy said it like this:

"You just talk in natural language, run it, copy-paste, and most of the time it just works. The code almost stops existing."

Old way? Developers wrote every line by hand. "This variable goes here. This function does that." Precise. Painful.

Vibe coding flips it. You say "make me a shopping mall." AI writes the whole thing. You go, "hmm, not quite -- change this part."

Coding by instinct. That's the name.

Sounds like a joke, right?

But Y Combinator's Jared Friedman dropped a bomb. 2025 W25 batch. About 25% of startups had 95% or more of their code generated by AI.

Y Combinator. Airbnb. Dropbox. That Y Combinator.

One in four companies they funded handed coding to AI.

The idea is simple. AI writes the code. Developers step in when something breaks. Used to be the other way around. Developers coded. AI helped when you got stuck. Now AI codes. Humans intervene when things go wrong.

A paper showed up in the journal *Software*. "Designing Microservices Using AI." Systematic literature review. A team from Argentina analyzed 43 studies, 2018 to 2024. What they looked at: how AI automates **microservice** design.

Plain terms? "Can we hand system architecture to AI?"

Here's what they found.

## Why Microservice Design Is Hell

Microservices. You split one big program into smaller services.

Think of it like a Chinese restaurant.

A real one is simple. "Delivery! Two noodles, sweet-and-sour pork combo!" "Coming right up!" Done.

Now imagine a computer running that restaurant.

Same order comes in. Here's what happens.

Order service asks inventory: "Got noodles for two?" Inventory: "Checking... yes." Order service again: "Soy paste?" "Checking... yes." "Pork?" "Checking... yes."

Then order service tells noodle-boiling service "boil two." Stir-fry service: "fry two." Pork service: "fry one." Noodle service pings stir-fry: "noodles ready." Pork service pings sauce: "done."

A human? Two sentences. Done.

The computer? Thirty calls.

But here's the worse part. Sauce service breaks? Runs out? Whole pork dish stops. Entire order freezes. Need another function to make new sauce.

A human? Just makes the sauce.

That's why microservice design is hell. Where does one service end and another begin? Cut too small -- drowning in communication overhead. Too big -- why'd you even split it?

Even seasoned devs go, "pickled radish is simple, let's separate it." Then every order calls the radish service. System tanks.

## How AI Tackles This

That paper reviewed 43 studies. Three approaches.

**First: read code, find patterns.** Clustering. Online store example. "Product lookup" and "inventory check" always fire together. Group them. "Payment" and "point deduction" always happen together. Group them too. AI finds millions of these patterns. Humans take months. AI takes minutes.

**Second: read requirement docs.** "Users should search products." "Users should add to cart." "Users should check out." AI reads those sentences. Groups similar functions. Some tools use BERT -- a language model that gets context, not just words. It knows "product search" and "find items" mean the same thing.

**Third: learn from actual usage.** Analyze logs from a running system. Which features get hammered? Which services chat too much? Too chatty -- merge. Too bloated -- split. Machine learning finds the sweet spot.

## What If AI Designed the Restaurant?

AI designs the Chinese restaurant system from scratch.

Analyzes a million past orders. "Noodle-pork combo ordered together 90% of the time?" One service. "Pickled radish on every order?" Don't separate it. Stick it in the order service. "Friday 6-8 PM orders spike?" Spin up three noodle-boiling instances.

Dumb computers ask "got noodles?" "got paste?" thirty times.

AI goes, "it's a noodle order -- obviously you need all of it." One shot.

Like a 20-year veteran owner. Hears "two noodles!" and his hands already move. AI learns the pattern. Skips the pointless confirmations.

Does things "roughly." Like a human. But way smarter than a computer's version of "roughly."

## Does It Actually Work?

The 43 studies say yes.

IBM built Mono2Micro. Name says it all. Takes a monolith -- big lump of a program -- splits it into microservices. First it scans all the code. Which class calls which class. Which data gets shared. Builds a graph. Like a subway map of dependencies.

Graph done? AI starts cutting. Tight connections stay together. Loose ones get separated. Companies tried it. Weeks of work, done in days. And it catches stuff humans miss. "Wait, this code was connected to that?"

SEMGROMI takes a different angle. Doesn't look at code. Reads user stories. "Users should log in." "Users should buy products." That kind of thing.

Groups similar sentences. "Login," "password reset," "sign up" -- authentication. One service. "Product view," "product search," "browse categories" -- product service. Sounds simple.

But hundreds of sentences? A human's brain melts. SEMGROMI handles it automatically.

Here's the kicker. It improves coupling and cohesion. Coupling: how tangled services are with each other. Lower is better. Cohesion: how related the functions inside one service are. Higher is better.

SEMGROMI beats what humans do by hand.

These tools aren't magic. They give you a first draft. Final call is still human. But it beats staring at a blank canvas.

## What AI Still Can't Solve

AI isn't all-powerful. Some problems remain.

Data consistency. Order service says "order complete." Inventory service says "out of stock." How do you prevent that mismatch? AI has no answer yet.

Distributed transactions. Payment succeeds. Shipping registration fails. Cancel the payment? Retry? AI can't predict every scenario.

Vague requirements. "Make it user-friendly." "It should be fast." AI can't interpret that. It needs numbers.

Real-time feedback loops. AI designs the system. You build it. Problems show up in production. Feeding runtime data back into the design? Still active research.

## What Does the Future Look Like?

The paper flags a few trends.

Generative AI is the biggest shift. Large language models help with design itself. "Design an online store as microservices." It proposes the whole architecture.

Reinforcement learning too. System learns on its own. Traffic spikes? Auto-scales. Error-prone spots? Auto-improved.

Most realistic approach: hybrid. AI drafts. Humans review. Humans catch what AI misses.
