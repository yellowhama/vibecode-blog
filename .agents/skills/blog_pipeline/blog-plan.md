# Blog Plan — 서사 구조 설계

기존 블로그 포스트(blog-only/)를 분석해서 Act 단위 서사 구조만 설계한다. 글 자체는 쓰지 않는다.

## 소스

- 소스 경로: $ARGUMENTS

## 프로세스

1. 소스 파일 전체를 읽는다
2. 아래 레퍼런스 파일을 읽는다:
   - `branding/narrative.md` — 3막 구조 (짜증→난리→파헤침), 6비트 체크리스트
   - `branding/BRAND.md` — 정체성 확인 (뭘 하고 뭘 안 하는 사람인가)
   - `easy_peasy/CATALOG.md` — 기존 콘텐츠 카탈로그
   - `easy_peasy/phase1/` — 기존 Act 파일 확인 (소재 겹침 방지)
3. 서사 구조를 설계한다:
   - 어떤 Act로 묶을 것인가 (Act 번호)
   - 몇 개의 씬으로 나눌 것인가
   - 각 씬의 핵심 한 줄 + 감정 비트
   - 소재 추출 포인트 (소스 파일명:라인 범위)
   - 씬 간 서사 브릿지 (이전 씬 끝 → 다음 씬 시작)
   - 3막 구조 매핑 (어디가 짜증, 어디가 난리, 어디가 파헤침)
4. 설계안을 사용자에게 제시한다

## 설계 규칙

### 3막 구조
- **짜증 (Frustration)**: 왜 빡쳤는가. 뭐가 안 됐는가.
- **난리 (Complication)**: 망함. 부서짐. 예상 밖의 문제.
- **파헤침 (Insight)**: 왜 이렇게 됐는가. 뭘 알게 됐는가.

### 6비트 체크리스트
각 씬에 최소 2개 이상:
1. **Scene** — 구체적인 장면 (시간, 장소, 행동)
2. **Wall** — 부딪힌 벽 (에러, 실패, 한계)
3. **Discovery** — 발견 ("아, 이거였구나")
4. **Experiment** — 시도 ("이러면 되려나?")
5. **Before/After** — 변화 (전:후 대비)
6. **Declaration** — 선언문 ("이게 답이다" / "이건 답이 아니다")

## 절대 규칙

- **소재 겹침 방지**: 기존 Act에서 이미 다룬 내용은 제외. phase1/ 기존 파일을 반드시 확인한다.
- **시간 참조 금지**: "6개월", "X주", "months ago" 같은 구체적 시간 표현을 설계에 포함하지 않는다. 시간 개념 자체를 빼라.
- **이야기 > 설명**: 각 씬이 "겪은 일"인지 "개념 설명"인지 판별한다. 설명이면 이야기로 전환할 방법을 제안한다.
- **서사 순서**: 독자가 모르는 제품/개념이 갑자기 등장하지 않도록 순서를 설계한다. 동기(왜 만드는가) → 재앙(망함) → 분석(왜 망했나) 순서.
- **행동이 전면**: 각 씬의 첫 줄은 겪은 일(행동/감정)로 시작한다. 개념이나 설명으로 시작하지 않는다.
- **"4줄 스펙" 금지**: Purpose/Reason/Method/Means는 "4가지 개념"이지 "4줄"이 아니다.

## 출력

서사 구조 설계안만 대화로 제시한다. 파일은 생성하지 않는다.
`/blog-draft`에서 이 설계를 기반으로 글을 작성한다.
