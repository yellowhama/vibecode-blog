# 자동화 워크프레임(중국집 비유로 이해하기)

당신 말이 맞습니다.  
“24시간 중국집을 AI 주방장으로 돌린다”는 건, 결국 **운영 설계도(워크프레임)**를 만드는 일입니다.

상세페이지 자동화도 똑같습니다.  
AI가 글/디자인을 ‘잘’하는 게 아니라, **가게가 24시간 굴러가게** 만드는 준비물이 필요합니다.

---

## 1) 중국집 24시간 자동화에서 필요한 준비물

- 재료/손질법: 어떤 재료를, 어떤 상태로, 어디에 보관?
- 레시피: 레시피 카드(정량/순서/시간/불/주의)
- 조리 SOP: 예외 처리(재료 없을 때, 불 조절 실패 등)
- 플레이팅: “이렇게 담는다” 표준
- 서빙: 주문 흐름/동선/포장 규칙
- 가격: 메뉴/옵션/할인/세트 규칙
- 카운터: 결제/영수증/매출 정리
- 컴플레인 처리: 환불/재조리/사과 멘트/기록
- 블랙리스트: 진상 패턴/대응/거절 문구
- 화이트리스트: 단골 선호/특별 요청/서비스 룰

핵심: 이걸 준비하면 AI는 “요리”만 하면 됩니다.  
준비가 없으면 AI는 매번 랜덤으로 요리하고, 사고가 납니다.

---

## 2) 상세페이지 자동화로 매핑하면(1:1 대응)

### 재료/손질법 -> SSOT(팩트) + 라벨/스펙

- 제품 팩트(라벨/구성품/재질/사이즈/주의사항)를 한 장으로 모음
- 파일: `ssot.yaml` (템플릿: `ssot_template.yaml`)

### 레시피 -> 섹션 레시피(섹션 플레이북)

- Hero/USP/Proof/FAQ/CTA를 “항상 같은 규칙”으로 만들게 함
- 위치: `rag/sources/01_section_playbook.md`

### 조리 SOP -> 오케스트레이터(순서 + 산출물 계약)

- AI가 말로 끝내지 않고 **파일을 생성**하게 함
- 위치: `prompts/00_orchestrator.md`
- 산출물: `01_intake_report.md`, `02_questions_to_answer.md`, `03_section_plan.json`, `04_copy_deck.md`, `05_wireframe.md`, `06_colors.json`, `07_image_prompts.md`, `08_shot_list.md`, `09_qa_report.md`, `run_summary.md`

### 플레이팅 -> 블록 와이어프레임(디자인 블록)

- “예쁘게”가 아니라 “항상 같은 블록 조립”으로 안정화
- 위치: `rag/sources/03_design_blocks.md`

### 서빙 -> 출력 채널(HTML/CMS/디자인툴)

- 어디에 올릴지는 나중 문제. 초안은 중립 포맷으로 시작 가능
- 확장: pencil MCP, HTML 렌더러, CMS 변환기

### 가격/옵션 -> 가격/프로모션 룰(구현됨)

- 옵션/세트/할인/무료배송 같은 규칙이 있어야 “구매 결론”이 흔들리지 않음
- 현재: SSOT에 빈칸으로 두고 질문으로 뽑는 방식
- 위치: `rag/sources/06_pricing_rules.md`

### 카운터/정책 -> 배송/교환/환불/AS(구현됨)

- 필수 고지/정책이 없으면 QA에서 계속 터짐
- 위치: `rag/sources/07_policy_rules.md`

### 컴플레인 처리 -> QA + 클레임 대응 문구(구현됨)

- 과장/근거 부족/오해 소지가 “컴플레인”의 원인
- 현재: `rag/sources/05_qa_rules.md`로 최소 가드레일 있음
- 위치: `rag/sources/08_support_playbook.md` (FAQ/대응 문구)

### 블랙/화이트리스트 -> 금지/허용 주장 리스트(구현됨)

- 블랙리스트: 금칙어, 근거 없는 표현, 비교 표현
- 화이트리스트: 근거가 있는 주장(라벨/스펙/인증 기반)
- 위치: `rag/sources/09_claims_allow_deny.md`

---

## 3) 지금까지 “이미 준비된 것” 체크(현재 레포 기준)

- SSOT 템플릿: `ssot_template.yaml`
- 오케스트레이터: `prompts/00_orchestrator.md`
- 작은 RAG 11종(기본원리/톤/섹션/포지셔닝/블록/이미지/QA/가격/정책/CS/클레임): `rag/sources/*`
- RAG 인덱스/검색/번들 생성:
  - `rag/scripts/build_index.mjs`
  - `rag/scripts/query.mjs`
  - `rag/scripts/make_prompt_bundle.mjs` -> `prompt_bundle.md`

---

## 4) “24시간 운영” 다음 단계(우선순위)

1. SSOT 표준화 강화: 필드 확장 + (가능하면) 스키마 검증
2. 출력 어댑터: `05_wireframe.md` -> (선택) Pencil MCP 레이아웃 / HTML / 특정 마켓 템플릿 변환
3. 운영 데이터 루프: 자주 나오는 문의/클레임을 SSOT + RAG에 반영해서 “다음엔 자동으로 예방”

지금은 “초안 공장”이 기본 운영 규정(가격/정책/CS/클레임)까지 갖춘 상태입니다.  
이제 남은 건 **어디에 올릴지(채널)**와 **계속 학습하게 만드는 루프**입니다.
