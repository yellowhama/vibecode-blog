# Claims Allow/Deny (RAG)

목표: 상세페이지에서 **“말해도 되는 것/말하면 안 되는 것”**을 분리해서, 과장/오해/클레임을 줄인다.

## 근거 레벨(이 기준으로 문장을 판단)

- `FACT`: SSOT에 있는 정보(라벨/스펙/구성품/치수/재질 등)
- `TODO`: 확인이 필요한 정보(정책/인증/수치/효과 등)
- `[ASSUMPTION]`: 추정(쓴다면 태그를 붙이고, 문장을 약하게)

## 허용(Allow) 주장 패턴

- 구성품/스펙/치수/재질처럼 “있는 그대로” 말할 수 있는 것(FACT 기반)
- 사용 방법/관리 방법(“이렇게 쓰면 편해요” 수준, 단정/보장 금지)
- 구매 전 체크리스트(“이걸 확인해 주세요”)
- 비교가 아닌 “상황 적합” 표현
  - 예: “이런 상황에서 유용합니다”, “이런 분께 추천합니다”

## 조건부 허용(근거가 있을 때만)

- 인증/테스트/수치/효과:
  - 인증 번호, 시험 성적서, 측정 기준, 출처 링크가 SSOT에 있을 때만.
  - 없으면 `TODO`로 남기고, 본문에서는 단정하지 않는다.
- “무료/무상/평생”:
  - 조건(기간/대상/범위)이 있을 때만.

## 금지(Deny) 주장 패턴(바로 삭제)

- 절대 표현: “100%”, “무조건”, “완벽”, “절대”, “영구”
- 결과 보장: “무조건 좋아진다”, “반드시 해결”, “효과 확실”
- 최상급/최저가: “최고”, “1위”, “역대급”, “최저가” (근거 없으면 금지)
- 타사 비교: “OO보다 낫다”, “시장 최고” (근거 없으면 금지)
- 공포/압박: “지금 안 사면 손해”, “안 쓰면 큰일”
- 의료/건강 효능 단정(식품/생활용품): 치료/예방/완치 암시

## 금지 문장을 “안전한 문장”으로 바꾸는 방법

- “효과”를 말하고 싶으면 -> “구조/재질/설계” 같은 FACT로 바꾼다.
  - 나쁨: “소음을 완벽 차단”
  - 좋음: “밀폐형 구조로 설계됨(소음 차단 수준은 사용 환경에 따라 다를 수 있음)”
- “최고”를 말하고 싶으면 -> “특징 1개”를 구체적으로 말한다.
  - 나쁨: “업계 최고 품질”
  - 좋음: “OO 재질/OO 공정을 사용(자세한 스펙: TODO/FACT)”
- “모두에게”를 말하고 싶으면 -> “추천 대상/비추천 대상”으로 나눈다.

## QA 체크리스트(자동 점검용)

- 모든 주장 문장에 “근거(FACT/TODO/ASSUMPTION)”가 연결되는가?
- 금지 패턴(절대/보장/비교/최상급)이 섞여 있지 않은가?
- 정책/가격/배송/AS처럼 클레임이 큰 영역이 TODO로 남아 있지는 않은가?
