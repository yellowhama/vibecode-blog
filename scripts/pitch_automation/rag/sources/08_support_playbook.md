# Support Playbook (RAG)

목표: 상세페이지 초안이 “클레임을 부르는 글”이 아니라, **문의/문제 상황을 미리 정리해 주는 글**이 되게 만든다.

## FAQ 작성 규칙(짧고 단단하게)

- 질문은 **고객이 실제로 하는 말**로 쓴다.
- 답변은 2~4줄. 길면 불릿 3개로.
- “정확히는 확인이 필요”한 내용은 `TODO`로 남기고, 확인 경로(판매처/담당자)를 적는다.
- FAQ는 “광고”가 아니라 “오해 방지”다. 과장 금지.

## 자주 쓰는 FAQ 뼈대(템플릿)

- Q. 배송은 얼마나 걸리나요?
  - A. `TODO` (판매처/마켓 확정 후 안내). 정확한 일정은 결제 후 안내되는 배송 정보를 참고해 주세요.
- Q. 교환/반품은 어떻게 하나요?
  - A. `TODO` (가능 기간/비용/접수 방법 확인 필요). 구매 페이지의 교환/반품 정책을 먼저 확인해 주세요.
- Q. 구성품이 뭐가 들어 있나요?
  - A. SSOT의 구성품 리스트를 그대로 복사한다(모르면 TODO).
- Q. 사용 방법이 어렵지 않나요?
  - A. “3단계 사용법”으로 쓴다(예: 꺼내기 -> 설치 -> 사용).
- Q. 호환/규격이 맞는지 모르겠어요(전자/자재)
  - A. “체크해야 할 3가지”를 준다 + 모르면 TODO.

## 컴플레인 대응 톤(말투 규칙)

- 먼저 공감 1문장, 다음에 사실/절차를 짧게.
- 책임 소재를 따지기 전에 “확인할 정보 2~3개”를 요청.
- “불가능합니다” 대신 “가능/불가 조건”으로 말한다(조건이 없으면 TODO).

## 문제 유형별 응답 템플릿(복붙용)

- 배송 지연:
  - “불편을 드려 죄송합니다. 현재 배송 상태는 `TODO`(조회 필요)입니다. 주문번호/수령자 정보를 주시면 확인 후 안내드리겠습니다.”
- 오배송/누락:
  - “받으신 구성품을 사진으로 1장만 부탁드립니다. 확인 후 누락/오배송 여부를 판단하고 다음 조치를 안내드리겠습니다.”
- 초기 불량/하자:
  - “불편을 드려 죄송합니다. 하자 부위를 사진/영상으로 공유해 주시면 확인 후 교환/환불 가능 여부를 안내드리겠습니다(정책: TODO).”
- 사용 방법 문의:
  - “사용 환경(모델/사이즈/상태)을 알려주시면 1)원인 후보 2)해결 순서로 안내드리겠습니다.”

## 에스컬레이션(사람에게 넘겨야 하는 경우)

- 안전 이슈(부상/화재/식중독 의심 등)
- 법/의료 효능 주장, 분쟁 조짐(협박/고소 등)
- 환불/보상 금액 협상, 반복 클레임(진상 패턴)

## 학습 루프(시스템으로 굳히기)

- 같은 질문이 3번 나오면: SSOT에 필드 추가 또는 FAQ를 고정 문구로 만든다.
- 자주 터지는 오해가 있으면: `09_claims_allow_deny.md`에 금지/대체 문장을 추가한다.
- 정책이 확정되면: `07_policy_rules.md`의 TODO를 실제 값으로 바꾸는 게 아니라, SSOT에 정책 링크/요약을 추가한다.
