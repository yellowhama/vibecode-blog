## 시즌 개요

**시즌1 테마**: "바이브 코딩의 기초 — 왜 터지고, 어떻게 안 터지게 하는가"

10에피소드. 블로그 기반 스토리 EP (Act 1-4)와 독립 SEO/에버그린 EP를 교차 배치한다.
전반부(EP01-04)는 바이브 코딩의 4가지 핵심 실패 패턴을 하나씩 다루고,
중간에 독립 EP(EP05-07)로 검색 트래픽과 신규 시청자를 유입하며,
후반부(EP08-10)에서 종합하고 시즌을 마무리한다.

**배치 순서** (교차 배치):
```
EP01 → EP05 → EP02 → EP06 → EP03 → EP07 → EP04 → EP08 → EP09 → EP10
```

이유: 스토리 EP 사이에 독립 EP를 끼워서 (1) 신규 시청자 진입점을 만들고 (2) 스토리 EP에 피로를 주지 않으며 (3) 알고리즘에 다양성을 보여준다.

## EP01: "스펙이 뭔가?"

- **주제**: 스펙 없이 코딩하면 망하는 이유, 스펙이 뭔지, 어떻게 만드는지
- **교육 목표**: 시청 후 "내가 뭘 만드는지" 한 문장으로 적는 습관 시작
- **블로그 소스**: act1-en.md (23/25, Grade A)
- **콘텐츠 필라**: AI 기초 (40%)
- **3H 유형**: Hub
- **내러티브 구조**: Problem-Solution

**핵심 비주얼 메타포**: 건물 = 코드
- 청사진 있으면: 기초 → 프레임 → 벽 → 지붕, 순서대로 올라감
- 청사진 없으면: 블록 랜덤 쌓기 → 흔들 → 붕괴
- 60초 이상 확장 (Scene3 전체)

**Aha 모먼트**: "스펙은 100페이지 문서가 아니다. 한 문장이다: '내가 뭘 만드는가?'"

**감정 곡선**:
```
흥분(AI 발견!) → 자신감(다 만들 수 있어!) → 공포(월요일 아침) → 명확함(스펙 = 한 문장) → 성장(스케이트보드→자전거→자동차)
```

**제작 난이도**: Medium
- Vee 씬: 8샷 (책상 공간)
- 다이어그램: 9샷 (건물 메타포, 화이트보드 공간)
- 총 ~24샷, 3분 타겟

**의존성**: 없음 (시즌 첫 에피소드)

**Shorts 추출 계획**:
1. Hook 클립 (0:00-0:15) — "이 순간 모든 바이브 코더가 살아있음을 느낀다" + 폭발
2. 건물 붕괴 비주얼 (Core 중) — 블록 쌓기 → 붕괴 30초
3. "스펙은 한 문장" 리빌 (Aha moment) — 15초

## EP02: "왼팔이 28개"

- **주제**: SDD(소프트웨어 디자인 문서), 컨텍스트 손실, SSOT(단일 진실 원천)
- **교육 목표**: 시청 후 CLAUDE.md나 .cursorrules 같은 환경 파일의 가치 이해
- **블로그 소스**: act2-en.md (22/25, Grade A)
- **콘텐츠 필라**: AI 기초 (40%)
- **3H 유형**: Hub
- **내러티브 구조**: Problem-Solution

**핵심 비주얼 메타포**: 28개의 왼팔
- AI에게 캐릭터를 만들어달라고 했더니 왼팔이 28개인 괴물이 나옴
- 컨텍스트가 없으면 AI는 매번 다른 해석을 함
- 시그니처 장면: 화면 가득 왼팔이 쏟아짐 (30초+)

**Aha 모먼트**: "말은 휘발된다. 환경은 남는다. CLAUDE.md가 스펙을 대신 기억한다."

**감정 곡선**:
```
자신감(15페이지 스펙!) → 혼란(파일 30개가 안전?) → 분노(매번 다른 기술 스택) → 명확함(SSOT) → 성장(환경 파일 하나)
```

**제작 난이도**: Medium
- 시그니처 장면 "28개 왼팔"이 비주얼 제작의 핵심
- 파일 증식 애니메이션 (종이가 쌓이는 비주얼)

**의존성**: EP01 (스펙 개념 전제)

**Shorts 추출 계획**:
1. "28개 왼팔" 비주얼 개그 — 30초 (강력한 바이럴 후보)
2. "AI가 매번 다른 기술을 고른다" — 15초 공감 클립
3. SSOT 리빌 — "문서 하나 vs 30개" 비교 비주얼

## EP03: "벽 없는 아파트"

- **주제**: DDD(도메인 주도 설계), 코드 아키텍처, 순환 의존
- **교육 목표**: 시청 후 "코드에도 방이 필요하다" 이해, 폴더 구조의 가치
- **블로그 소스**: act3-en.md (23/25, Grade A) — 시리즈 최고 비주얼 메타포 밀도
- **콘텐츠 필라**: AI 기초 (40%)
- **3H 유형**: Hub
- **내러티브 구조**: Problem-Solution

**핵심 비주얼 메타포**: 벽 없는 아파트
- 주방에서 요리하면 기름이 침대로 튐
- 하나 고치면 세 개가 터짐
- 벽을 세우면: 각 방이 독립, 옆집 냉장고 못 열음
- 전기 울타리 = Rust 컴파일러 (경계를 넘으면 감전)
- 60초+ 확장 — 하나의 아파트 씬에서 카오스 → 질서로 진화

**Aha 모먼트**: "내가 버그를 만든 게 아니다. 구조가 버그다."

**감정 곡선**:
```
혼란(새 기능 어디 넣지?) → 좌절(하나 고치면 셋 터짐) → 분노(순환 의존) → 명확함(벽 = 경계) → 두려움(금요일→월요일 에이전트 사망)
```

**제작 난이도**: Hard
- 아파트 메타포 전체를 하나의 진화하는 씬으로 구축
- 벽 세우기 전/후 비교가 핵심
- 가장 비주얼리 풍부한 에피소드

**의존성**: EP01 (스펙), EP02 (SDD 개념)

**Shorts 추출 계획**:
1. "벽 없는 아파트에서 요리" 비주얼 개그 — 30초
2. "하나 고치면 셋 터짐" 공감 클립 — 15초
3. "전기 울타리 = 컴파일러" 개그 — 15초

## EP04: "열기 무서운 상자"

- **주제**: TDD(테스트 주도 개발), 테스팅의 가치, "코드를 못 읽어도 검증할 수 있다"
- **교육 목표**: 시청 후 "테스트 = 용기"라는 프레이밍 전환
- **블로그 소스**: act4-en.md (21/25, Grade B+)
- **콘텐츠 필라**: AI 기초 (40%)
- **3H 유형**: Hub
- **내러티브 구조**: Problem-Solution

**핵심 비주얼 메타포**: 슈뢰딩거의 상자
- 코드가 맞는지 틀린지 모른 채 상자를 바라보는 Vee
- 상자를 열면 → 죽은 고양이 (에러) 또는 살아있는 고양이 (성공)
- 테스트 = 상자를 열 용기를 주는 것
- 품질 게이트: 상자를 체크포인트에 통과시킴. 초록불 = 통과, 빨간불 = 반려

**Aha 모먼트**: "테스트는 검증이 아니다. 용기다."

**감정 곡선**:
```
불안(맞는 건지 모르겠어) → 공포(건드리면 터질까) → 지침(수동 테스트 반복) → 명확함(테스트 = 용기) → 자신감(6,260개 체크마크)
```

**제작 난이도**: Medium
- 슈뢰딩거 상자 비주얼은 비교적 단순
- TDD 설명 구간에 비주얼 재해석 필요 (추상적 내용)
- 6,260 체크마크 벽 채우기 = 만족스러운 비주얼

**의존성**: EP01-03 (프레임워크 연속체)

**Shorts 추출 계획**:
1. 슈뢰딩거 상자 열기 비주얼 개그 — 15초
2. "테스트는 검증이 아니다. 용기다." 명대사 클립 — 15초
3. 6,260 체크마크 벽 채우기 ASMR — 30초

## EP05: "바이브코딩이 뭔데?"

- **주제**: 바이브 코딩의 정의, 역사, 어디까지 가능한지, 한계는 뭔지
- **교육 목표**: 시청 후 "바이브 코딩"을 다른 사람에게 설명 가능
- **블로그 소스**: 신규 작성 (Help 콘텐츠, 에버그린)
- **콘텐츠 필라**: AI 기초 (40%)
- **3H 유형**: Help (검색 트래픽 타겟)
- **내러티브 구조**: Mystery-Reveal

**핵심 비주얼 메타포**: 요리 = 코딩
- 레시피 없이 냉장고 재료로 요리 = 바이브 코딩
- AI = 전자레인지 (빠르지만 컨트롤 제한)
- 스펙 = 레시피 (있으면 매번 같은 맛)

**Aha 모먼트**: "바이브 코딩은 '코드를 안 쓰는 것'이 아니라 'AI와 함께 의도를 코드로 번역하는 것'"

**감정 곡선**:
```
호기심(바이브 코딩이 뭔데?) → 흥분(와 이렇게 쉬워?) → 의심(근데 진짜 되나?) → 명확함(가능 범위 + 한계) → 자신감(시작하는 법)
```

**제작 난이도**: Easy
- 정의 + 예시 중심, 서사 복잡도 낮음
- 다이어그램 비중 높음 (비교 차트, 타임라인)
- SEO 키워드: "vibe coding", "what is vibe coding", "AI coding for beginners"

**의존성**: 없음 (독립 에피소드, 신규 시청자 진입점)

**Shorts 추출 계획**:
1. "바이브 코딩 30초 설명" — 정의 클립
2. "전자레인지 = AI" 비주얼 개그 — 15초
3. "바이브 코딩 vs 전통 코딩" 비교 차트 — 30초

## EP06: "10분만에 AI 에이전트"

- **주제**: AI 에이전트 빌드 튜토리얼 (빌드위드미 포맷)
- **교육 목표**: 시청 후 간단한 AI 에이전트를 직접 만들어볼 수 있음
- **블로그 소스**: 신규 작성 (실전 활용 Tutorial)
- **콘텐츠 필라**: 실전 활용 (25%)
- **3H 유형**: Help (검색 트래픽 타겟)
- **내러티브 구조**: Build-Along (스텝 바이 스텝)

**핵심 비주얼 메타포**: 로봇 조립
- 작은 파츠가 하나씩 조립되어 로봇이 완성됨
- 각 파츠 = 에이전트의 구성요소 (입력, 판단, 출력, 메모리)
- 완성된 로봇이 혼자 움직이기 시작

**Aha 모먼트**: "에이전트는 코드가 아니다. 판단의 흐름이다."

**감정 곡선**:
```
호기심(에이전트 만들고 싶어) → 집중(따라하기) → 흥분(움직인다!) → 놀람(혼자 판단한다?) → 자신감(나도 만들 수 있네)
```

**제작 난이도**: Hard
- 빌드위드미 포맷은 스크린캐스트 + 2D 비주얼 혼합
- 다이어그램 비중 높음 (아키텍처 플로우)
- 코드 스니펫을 비주얼로 표현하는 방법 필요

**의존성**: EP01 (스펙 개념), EP05 (바이브 코딩 정의)

**Shorts 추출 계획**:
1. "에이전트 30초 설명" — 정의 + 로봇 조립 비주얼
2. "AI 에이전트가 혼자 판단하는 순간" 비주얼 — 15초
3. 완성 순간 "움직인다!" 리액션 — 15초

## EP07: "AI는 왜 헛소리를 하나"

- **주제**: AI 할루시네이션의 원리, 왜 발생하는지, 어떻게 줄이는지
- **교육 목표**: 시청 후 할루시네이션이 "버그"가 아니라 "구조적 특성"임을 이해
- **블로그 소스**: 신규 작성 (개념 설명 Concept)
- **콘텐츠 필라**: AI 기초 (40%)
- **3H 유형**: Hub (시리즈 코어)
- **내러티브 구조**: Mystery-Reveal

**핵심 비주얼 메타포**: 드림캐쳐
- AI의 응답 = 꿈. 대부분 말이 되지만, 가끔 이상한 꿈이 섞임
- 드림캐쳐 = 검증 시스템 (그물에 헛소리가 걸림)
- 그물이 없으면: 헛소리가 그대로 코드에 들어감

**Aha 모먼트**: "AI는 거짓말하는 게 아니다. 확신에 차서 틀린 거다. 마치 시험에서 자신있게 오답 쓰는 것처럼."

**감정 곡선**:
```
혼란(왜 자꾸 이상한 답을?) → 분노(아니 뻔히 아는 걸 틀려?) → 호기심(왜 그런 거지?) → 명확함(구조적 원인) → 실용(줄이는 법)
```

**제작 난이도**: Medium
- 미스터리-리빌 구조로 호기심 유지
- 확률 분포 / 토큰 예측 비주얼이 핵심
- 드림캐쳐 메타포는 시각적으로 아름다움

**의존성**: 없음 (독립 에피소드)

**Shorts 추출 계획**:
1. "AI가 자신있게 틀리는 순간" 비주얼 개그 — 15초
2. "드림캐쳐 = 검증" 비주얼 설명 — 30초
3. "할루시네이션 줄이는 3가지 방법" 팁 — 60초

## EP08: "바이브코더 5대 실수"

- **주제**: EP01-04에서 다룬 실패 패턴 5가지 종합 리스티클
- **교육 목표**: 시청 후 자신의 작업 방식에서 해당 실수를 발견할 수 있음
- **블로그 소스**: Acts 1-4 종합 편집
- **콘텐츠 필라**: AI 기초 (40%)
- **3H 유형**: Hub (높은 공유성)
- **내러티브 구조**: Listicle (카운트다운)

**5대 실수**:
1. 스펙 없이 시작한다 (EP01)
2. 컨텍스트를 AI에게 떠넘긴다 (EP02)
3. 구조 없이 파일을 늘린다 (EP03)
4. 테스트 없이 "되는 것 같다"고 믿는다 (EP04)
5. 실패를 기록하지 않는다 (EP01-04 공통)

**핵심 비주얼 메타포**: 5개의 함정 (구덩이)
- 각 실수 = 하나의 구덩이
- Vee가 하나씩 빠짐 → 빠져나옴 → 다음 구덩이
- 마지막에 5개 구덩이를 내려다봄 (전경)

**Aha 모먼트**: "이 5가지를 피하는 게 아니다. 5가지를 거치고 살아남는 시스템을 만드는 거다."

**감정 곡선**:
```
자신감(나는 안 그래) → 찔림(1번... 이거 나잖아) → 웃음(2-4번 연속 공감) → 명확함(종합) → 결의(시스템을 만들자)
```

**제작 난이도**: Easy
- 기존 에피소드 비주얼 재활용 가능
- 리스티클 구조 = 편집 효율 높음
- 높은 공유성 (태그하기 좋은 포맷)

**의존성**: EP01-04 (콜백 에피소드)

**Shorts 추출 계획**:

## EP09: "이 영상은 AI가 만들었다"

- **주제**: 메타/비하인드 — 이 시리즈 자체가 AI로 만들어진 과정 공개
- **교육 목표**: 시청 후 AI 비디오 파이프라인의 현실적 가능성과 한계 이해
- **블로그 소스**: 신규 작성 (비하인드)
- **콘텐츠 필라**: 비하인드 (15%)
- **3H 유형**: Hero (바이럴 잠재력 높음)
- **내러티브 구조**: Behind-The-Scenes reveal

**핵심 비주얼 메타포**: 커튼 뒤
- 영상 속 장면 → 뒤로 카메라 빠지면 → 파이프라인 노출
- Flux → Wan → Dia2 → FFmpeg 각 단계를 실제 결과물로 보여줌
- "마법 아님, 엔지니어링" 리빌

**Aha 모먼트**: "AI가 만든 게 아니라, AI를 도구로 쓴 거다. 판단은 내가 했다."

**감정 곡선**:
```
놀람(이게 다 AI?) → 호기심(어떻게?) → 흥미(파이프라인 공개) → 현실감(이것도 안 되고 저것도 안 됨) → 영감(나도 할 수 있겠다)
```

**제작 난이도**: Medium
- 실제 파이프라인 화면 캡처 + 2D 비주얼 혼합
- 실패 사례 (아티팩트, 왜곡) 를 보여주는 것이 핵심
- 메타 에피소드라 자기참조적 유머 가능

**의존성**: EP01-08 (시리즈 축적 후 공개 효과 극대화)

**Shorts 추출 계획**:
1. "이 장면 AI가 만듦" 비포/애프터 — 30초
2. "AI가 만든 최악의 실패" 비주얼 개그 모음 — 60초
3. "파이프라인 30초 요약" 속도감 있는 플로우 — 30초

## EP10: "좌절에서 시스템으로"

- **주제**: EP01-04를 관통하는 여정 정리. FDD→SDD→DDD→TDD 프레임워크 완성.
- **교육 목표**: 시청 후 "좌절→기록→구조→검증" 사이클을 자기 작업에 적용 가능
- **블로그 소스**: act5-en.md (16/25, Grade C) → 시즌 피날레 몽타주로 편집
- **콘텐츠 필라**: AI 기초 (40%)
- **3H 유형**: Hub (시즌 피날레)
- **내러티브 구조**: Montage + Callback

**핵심 비주얼 메타포**: 나선형 계단
- 좌절의 반복이 아니라 나선형 상승
- 같은 문제를 만나도 이제는 시스템이 있음
- EP01-04의 시그니처 비주얼이 빠르게 스쳐감 (콜백 몽타주)

**Aha 모먼트**: "좌절이 스펙이 된다. 스펙이 시스템이 된다. 시스템이 자유가 된다."

**감정 곡선**:
```
회상(EP01-04 플래시백) → 거리감(멀리서 보니 패턴이 보인다) → 명확함(프레임워크 전체상) → 감동(Vee의 성장) → 열림(시즌2 티저)
```

**제작 난이도**: Medium
- EP01-04 비주얼 재활용으로 제작 부담 감소
- 몽타주 편집이 핵심 (빠른 컷 + 감정 음악)
- 시즌 피날레다운 감정적 무게감 필요

**의존성**: EP01-04 필수 (콜백 에피소드)

**Shorts 추출 계획**:
1. "좌절→스펙→시스템→자유" 명대사 클립 — 15초
2. EP01-04 베스트 장면 몽타주 — 60초
3. 시즌2 티저 — 15초

## 시즌2 방향 (예고)

시즌1이 "왜 터지는가"를 다뤘다면, 시즌2는 "어떻게 안 터지게 만드는가"를 다룬다.

가능한 주제:
- 프롬프트 엔지니어링 깊이 파기
- MCP (Model Context Protocol) 실전
- AI 에이전트 오케스트레이션
- 비용 최적화 (토큰, 컴퓨트)
- 팀에서의 바이브 코딩

시즌2 기획은 시즌1 EP05 이후 시청자 반응 데이터를 수집한 뒤 결정한다.
