# Twitter Playbook — 일일/주간 실행 가이드

> 전략은 `STRATEGY.md`. 롤모델/데이터는 `REFERENCE.md`.
> 여기는 **매일/매주 실제로 뭘 하는가**.

---

## Phase 1: 씨 뿌리기 (현재 → MUSU 런칭 전)

### 매일 할 것

**1. 리플라이 10~20개 (30분~1시간)**

타임라인을 훑으면서 진짜 할 말이 있는 대화에 끼어든다.

대상 찾는 법:
- "AI agent" "vibe coding" "MCP" "Claude" "Cursor" 검색
- @levelsio @tdinh_me @mckaywrigley 등의 트윗과 리플라이 타래
- Indie Hacker / AI builder 커뮤니티 대화

리플라이 쓰는 법:
- 상대 말에 반응. 내 얘기가 아님.
- "이거 나도 겪었는데" 식의 경험 공유
- 구체적 디테일 있으면 좋음 ("5개 에이전트가 GPU 하나 놓고 싸움")
- 질문도 좋음 ("What stack? Curious how the deploy went.")

절대 안 하는 것:
- 자기 콘텐츠 끼워넣기 ("I wrote about this...")
- 링크 달기
- 팔로워 많다고 무조건 리플라이
- "Great thread!" 같은 빈말

**2. 타임라인 읽기 (15분)**

AI/dev 타임라인 훑기. 리플라이할 거리 찾기.
트렌딩 화제 파악. 이건 소재가 아니라 맥락.

### 매주 할 것

**1. 원본 트윗 2~3개 (일요일 배치 세션)**

프로세스:
1. 이번 주 작업 기록 확인 (git log, 삽질 메모, Claude 대화)
2. "이거 사람들한테 말할 만한가?" 필터
3. branding/voice.md 톤으로 작성
4. branding/narrative.md 3막 압축 패턴 적용
5. branding/examples.md 광고 카피 체크
6. 유저에게 보여주고 승인
7. queue JSON에 넣기

소재 뽑는 질문:
- "이번 주에 뭐 부서졌나?"
- "이번 주에 뭘 새로 알았나?"
- "이번 주에 뭐가 빡쳤나?"
- "이번 주에 뭘 만들었는데 안 됐나?"

**2. 큐 관리**

- `twitter/queue/YYYY-wWW.json` 파일 확인
- draft → approved 상태 전환 (유저 승인 후)
- GitHub Actions cron이 approved → posted 처리

### 안 할 것

- 에디토리얼 캘린더 (미디어 회사 아님)
- 매일 원본 트윗 의무 (할 말 없으면 안 함)
- 팔로워 수 체크 (KPI 아님)
- "이번 주 성과" 식의 요약 트윗 (광고)

## Phase 전환 기준

### Phase 1 → Phase 2 전환 시점

**조건 (전부 AND):**
1. MUSU가 런칭됨 (실제 유저가 쓸 수 있는 상태)
2. 팔로워 200+ (Day 1 유저 풀)
3. 공유할 숫자가 있음 (다운로드 수, 유저 수, 뭐라도)

**전환되면 바뀌는 것:**
- 원본 트윗 빈도: 주 2~3 → 매일 1+
- 콘텐츠: 삽질 기록 → 매출/유저/피드백 공유
- Build in Public 시작: 스크린샷, 숫자, 마일스톤
- Product Hunt + Hacker News 동시 런칭 준비

**전환돼도 안 바뀌는 것:**
- 나이키 룰 (제품 밀지 않음)
- 리플라이 대화 (계속)
- 광고 카피 체크 (계속)
- 유저 승인 후 발행 (계속)

## 뉴스레터 연결 (Phase 1 후반)

### 언제 시작하나

팔로워 200~300 되면 고려.

### 왜

- 이메일은 소셜 대비 4x 높은 engagement
- Twitter 알고리즘 변경에 독립적 ("소유한 오디언스")
- 런칭 알림을 직접 보낼 수 있음

### 파이프라인

```
Twitter 리플라이/트윗 → 프로필 방문 → 바이오 링크 → 뉴스레터 구독
                                                      ↓
                                              MUSU 런칭 알림
```

지금 당장은 아님. 바이오에 블로그 링크 하나로 충분.

## 시간 투자 가이드

### Phase 1 (현재)

| 활동 | 시간/일 | 빈도 |
|------|---------|------|
| 리플라이 | 30분~1시간 | 매일 (주말 빼도 됨) |
| 타임라인 읽기 | 15분 | 매일 |
| 원본 트윗 작성 | 1시간 | 주 1회 (일요일 배치) |
| **총** | **~1시간/일** | |

트윗에 하루 1시간 이상 쓰지 않는다. 제품 만드는 게 본업.

### Phase 1 팔로워 성장 기대치

| 시점 | 예상 팔로워 | 비고 |
|------|-----------|------|
| 1개월 | 100~200 | 매일 리플라이 + 주 2~3 트윗 기준 |
| 2개월 | 300~500 | 모멘텀 시작 |
| 3개월 | 700~1,000 | 90일 = 최소 유의미 결과 시점 |

30~50%/월 성장이 꾸준한 노력으로 달성 가능한 범위.
이보다 빠르면 좋은 거고, 느려도 정상.

### 참고: 개발자 도구 첫 100명 유저 실제 사례

한 개발자의 문서화된 첫 100명 유저 획득 채널:

| 채널 | 유저 수 |
|------|--------|
| Reddit (니치 서브레딧) | 60 |
| 직접 아웃리치 | ~20 |
| Discord 커뮤니티 | ~15 |
| Twitter 스레드 | 3 |
| Twitter 일반 포스트 (600+ 팔로워) | 0 |

→ Twitter는 초기 유저 획득 채널이 아님. 관계 구축 채널임.
