# Policy Rules (RAG)

목표: 상세페이지에 **배송/교환/환불/AS 같은 “카운터 규정”**을 안전하게 넣는다.  
원칙: **모르면 만들지 말고, `TODO`로 남기고 질문으로 돌린다.**

## 정책 문장 기본 규칙

- “정책”은 감성 카피가 아니라 **정보**다. 짧게, 한 문장씩.
- **단위/조건**을 같이 쓴다. (예: “3만원 이상 무료배송”, “영업일 기준”)
- “무조건/항상/절대” 같은 단어는 정책 파트에서도 금지.
- 판매처/마켓이 정해지지 않았으면: “정확한 정책은 최종 판매처 정책을 따릅니다”를 기본값으로 둔다.

## 필수 항목 체크리스트(모르면 TODO)

- 배송: 택배사/출고일/배송비/무료배송 조건/도서산간 여부
- 교환/반품: 가능 기간/불가 조건/왕복 배송비/접수 방법
- 환불: 처리 기준/기간(영업일)/환불 수단
- AS/보증: 대상/기간/접수 방법(전자제품이면 거의 필수)
- 문의 채널: 연락처 또는 “문의하기” 경로 + 응대 시간

## 모르면 이렇게 쓰기(TODO 템플릿)

- 배송: `배송 정책: TODO (판매처/마켓 확정 후 기입)`
- 교환/반품: `교환/반품: TODO (가능 기간/비용/불가 조건 확인 필요)`
- 환불: `환불: TODO (처리 기간/방법 확인 필요)`
- AS/보증: `AS/보증: TODO (대상/기간/접수 경로 확인 필요)`
- 공통 안전문구: `정확한 정책은 최종 구매 페이지(판매처)에서 다시 확인해 주세요.`

## 오해가 자주 생기는 지점(미리 차단)

- “단순 변심”은 사람마다 해석이 다르다 -> **조건을 구체화**하거나 TODO로 둔다.
- “개봉/사용” 여부 -> 정책이 없으면 **단정하지 말고** “판매처 정책 확인”으로 처리.
- “맞춤 제작/재단/각인” 같은 주문 제작 요소가 있으면 -> 반품/환불 조건을 더 명확히 해야 한다(없으면 TODO).

## 상세페이지에 넣는 추천 레이아웃(정책 박스)

- 제목: `배송/교환/환불 안내`
- 형식: 표 또는 아코디언(접었다 펼침)
