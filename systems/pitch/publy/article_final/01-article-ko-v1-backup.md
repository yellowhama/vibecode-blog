# 클로드 코드로 상세페이지 초안 공장 만들기

---

## 먼저 한 줄

"상세페이지를 잘 쓰는 법"이 아닙니다.
**상세페이지 초안 세트를 반복 생산하는 공장**을 만듭니다.

여기서 "자동화"란,
초안은 AI가 뽑고, 최종 승인은 사람이 하는 상태입니다.

---

## 1. 상세페이지 하나에 반나절

월요일 아침.
새 상품이 왔다.
사과. 2킬로 한 박스.
상세페이지를 만들어야 한다.

정보를 모은다.
슬랙에서 찾는다. 없다.
노션에서 찾는다. 반만 있다.
엑셀에서 찾는다. 버전이 3개다.
머릿속에서 꺼낸다. 확실하지 않다.

사진.
정면샷 하나. 형광등 아래에서 찍은 것.
배경 정리 안 됐다. 사이즈 비교 없다.
"이거 하나로 뭘 어쩌라고."

정책.
배송비? 모른다.
교환/환불? 아직 안 정해졌다.
원산지? 라벨 확인해야 한다.

그래도 만든다.
상사가 "오늘 중으로"라고 했으니까.

3시간 걸렸다.

뭘 했는지 돌아보면.
카피 쓰는 데 40분.
사진 잘라 붙이는 데 30분.
정책 안내 찾아서 끼워 넣는 데 20분.
검수하는 데 30분.

근데 진짜 시간을 잡아먹은 건 이게 아니다.

정보 찾는 데 1시간.
"이 가격 맞아?" "배송비 확인해주세요" "원산지 어디더라?"
슬랙에 물어보고, 답 기다리고, 다시 물어보고.

만드는 시간보다 찾는 시간이 더 길었다.

다음 주. 헤드폰이 왔다.
또 처음부터.
정보 모으고, 카피 쓰고, 사진 편집하고, 정책 넣고, 검수하고.
또 3시간.

그 다음 주. 폼보드.
또 처음부터. 또 3시간.

한 달이면 상품이 4~5개 온다.
4개 × 3시간 = 12시간.
한 달에 이틀 반을 상세페이지에 쓰고 있었다.

근데 진짜 문제는 시간이 아니었다.

매번 처음부터라는 거다.
저번에 사과 만들면서 겪은 시행착오가, 이번 헤드폰에 하나도 안 남는다.
매번 백지 상태에서 시작한다.
사람이 바뀌면 더하다. 인수인계? 그런 거 없다.

매번 처음부터.
매번 반나절.
매번 같은 실수.

이게 일인가, 노가다인가.

---

## 2. 공장이 필요하다

문제를 다시 봤다.

매번 3시간 걸리는 이유.
실력이 아니었다.
매번 처음부터 시작하기 때문이었다.

장인이 더 잘 만드는 방법.
한계가 있다.
한 사람이 하루에 만들 수 있는 페이지는 2~3개가 끝이다.

공장은 다르다.
같은 재료 넣으면, 같은 결과가 나온다.
재료만 바꾸면, 다른 제품이 나온다.
매번 처음부터가 아니라, 매번 같은 라인이 돌아간다.

여기서 중요한 거.

AI가 상세페이지를 "만들어주는" 게 아니다.
AI가 **공장을 만들어주는** 거다.

"사과 상세페이지 만들어줘."
이건 장인한테 부탁하는 거다. 한 번이면 끝이다.

"상세페이지 초안을 찍어내는 시스템을 만들자."
이건 공장을 세우는 거다.
사과도 되고, 헤드폰도 되고, 폼보드도 된다.
재료만 바꾸면 된다.

---

## 3. 설계도를 만든다

공장을 세우려면 설계도가 필요하다.
상세페이지 공장의 설계도는 간단하다.

**"제품 정보 한 장."**

제품에 대해 아는 걸 한 장에 모은다.
상품명. 카테고리. 가격. 구성. 크기. 무게.
사용법. 타겟. 배송. 교환/환불.

규칙은 하나다.

**아는 건 적는다. 모르는 건 비워둔다.**

사과로 해봤다.
책상 위에 사과 박스 놓고, 아는 것만 적었다.

| 항목 | 내용 |
|------|------|
| 상품명 | 부사 사과 |
| 카테고리 | 과일 |
| 한 줄 설명 | 먹는 생과일 |
| 구성 | 2kg (10과) 1박스 |
| 크기 | 손바닥 크기 (대략) |
| 사용법 | 세척 후 섭취 |
| 가격 | (비워둠) |
| 원산지 | (비워둠) |
| 배송 | (비워둠) |
| 교환/환불 | (비워둠) |

반이 비었다.

처음엔 불안했다. "이렇게 빈칸이 많은데 괜찮나?"
괜찮다.
비어있는 건 "아직 모른다"는 뜻이다.
채워 넣으면 다음에 더 좋아진다.

빈칸이 있으면 AI가 어떻게 하냐고?
빈칸은 빈칸으로 남긴다. 지어내지 않는다.
"가격: TODO (확인 필요)"라고 쓴다.
이건 나중에 사람이 채우면 된다.

여기서 절대로 하면 안 되는 게 있다.

**모르는 걸 적지 마라.**

"아마 경북일 거야" — 이건 추정이다.
사실 칸에 쓰면 AI가 사실로 받아들인다.
그러면 카피에 "경북산 사과"가 버젓이 나온다.
아닐 수도 있는데.
고객이 보고 산다. 경북이 아니면? 클레임이다.

사실, 추정, 질문.
이 셋을 섞으면, AI도 헷갈린다. 사람도 헷갈린다.
결국 나중에 전부 다시 확인해야 한다.

그래서 칸을 나눴다.

- **사실**: 라벨, 스펙표, 확인된 정보만
- **추정**: "아마 ~일 것 같다"는 따로 모음
- **질문**: 반드시 확인해야 할 것

이렇게 나누면 AI가 사실만 카피에 쓴다.
추정은 "확인 필요"로 남긴다.
질문은 "다음 루프에서 해결할 것"으로 정리한다.

적는 데 10분이면 된다.
이 한 장이 공장의 설계도다.

## 4. 첫 가동

설계도를 만들었다.
이제 공장을 돌린다.

도구는 Claude Code다.
터미널에서 돌아가는 AI 도구다.
채팅창이 아니라, 파일을 직접 만들어준다.

설계도(제품 정보 한 장)를 폴더에 넣고,
지시서(마스터 프롬프트)를 붙여넣고,
실행한다.

10분 뒤.
파일 11개가 생긴다.

| # | 파일 | 하는 일 |
|---|------|--------|
| 1 | 입력 점검 | 지금 뭐가 있고, 뭐가 없는지 |
| 2 | 품질 올리는 질문 | 이것만 답하면 다음에 확 좋아지는 질문 10개 |
| 2b | 디자인 리서치 | 이 카테고리에서 잘 팔리는 페이지는 어떻게 생겼나 |
| 3 | 섹션 기획 | 어디서 무슨 말을 할지 (리서치 기반) |
| 4 | 카피 초안 | 헤드라인, 본문, 버튼 문구 (2개씩) |
| 5 | 블록 배치 | 글과 사진이 어디에 들어가는지 |
| 6 | 색상 | 페이지 색깔 |
| 7 | 이미지 지시 | 사진 보정/보조 이미지 가이드 |
| 8 | 촬영 목록 | 다음에 찍어야 할 사진 |
| 9 | 검수 리포트 | 과장/금지 표현/빠진 고지 자동 체크 |
| 10 | 실행 요약 | 이번 결과 + 다음에 할 일 |

이게 있으면 뭐가 좋은가.

하나.
다음에 누가 맡아도 같은 방식으로 만든다.
"저번 담당자는 어떻게 했지?" 가 사라진다.

둘.
사진이 없어서 멈추지 않는다.
촬영 목록이 나온다. "다음에 이거 찍어오세요."

셋.
"어떻게 만들지?"를 공장이 알아서 조사한다.
같은 카테고리에서 잘 팔리는 페이지를 리서치하고, 설계 기준 3가지를 뽑아준다.
이걸 보고 섹션을 짜니까, 감으로 만드는 게 아니다.

넷.
검수를 사람이 하나하나 안 봐도 된다.
"100% 보장" 같은 표현은 자동으로 걸린다.

근데 첫 가동은 완벽하지 않다.
당연하다.
설계도에 빈칸이 많았으니까.

카피를 보면 TODO 투성이다.
"가격: TODO (확인 필요)."
"배송: TODO (정책 확인 후 입력)."

그런데.

**AI가 질문을 한다.**

[캡처 1: 품질 올리는 질문 목록]

"이것만 답해주시면 다음 초안이 확 좋아집니다."

질문 10개.
"가격이 얼마인가요?"
"원산지가 어디인가요?"
"배송은 어떻게 되나요?"
"타겟이 누구인가요?"

이게 핵심이다.
AI가 만들어주는 게 아니라,
**AI가 뭘 채워야 하는지 알려주는 거다.**

사진이 없어서 멈추는 게 아니라,
다음에 뭘 찍을지가 나온다.

## 5. 질문 5개. 다시 돌린다. 다르다.

첫 가동에서 AI가 던진 질문 10개.
그중 5개만 답했다.

| 질문 | 답 |
|------|---|
| 가격 | 12,900원 |
| 구성 | 2kg, 10과 |
| 원산지 | 경북 부사 |
| 배송 | 산지 직송, 상온택배 2~3일 |
| 타겟 | 가정용 간식, 명절 선물 |

설계도에 5줄 추가했다.
같은 공장을 다시 돌렸다.

결과가 다르다.

첫 번째 카피:
> "사과입니다. 세척 후 바로 드세요."

두 번째 카피:
> "경북 부사 사과, 2kg(10과) 한 박스. 산지에서 바로 보냅니다."

첫 번째 검수 결과: **불합격** — 핵심 정보 부족.
두 번째 검수 결과: **합격** — 사실 기반 카피, 보강 필요 항목 2개.

[캡처 4: 첫 번째 vs 두 번째 비교]

같은 공장. 재료만 보강했다.
결과가 이렇게 다르다.

이게 공장이다.
같은 설계도, 더 좋은 재료, 더 좋은 결과.
매번 처음부터가 아니라, 매번 이전보다 나아진다.

## 6. AI가 거짓말하면?

여기서 가장 많이 받는 질문.

"AI가 '최고의 사과'라고 쓰면 어쩌나요?"
"없는 인증을 만들어내면요?"
"가격을 지어내면요?"

세 가지 안전장치가 있다.

**첫째, 모르면 모른다고 한다.**

가격을 안 넣었으면, AI가 가격을 지어내지 않는다.
대신 이렇게 쓴다:

> 가격: TODO (판매처 확인 필요)

빈칸이 거짓보다 낫다.
빈칸은 "다음에 채우면 된다."
거짓은 "나중에 전부 다시 해야 한다."

**둘째, 금지 표현을 자동으로 잡는다.**

일부러 넣어봤다.
카피에 "최고의 사과"를 적었다.

검수 리포트가 바로 잡았다:
> "최고" — 비교 근거 없음. 삭제 권장.
> 수정 제안: "경북 부사 사과입니다."

[캡처 5: TODO 안전 장치]

[캡처 6: 금지 표현 자동 검수]

**셋째, 근거 없는 수치를 차단한다.**

"당도 13 brix" — 이건 어디서 나온 숫자인가?
근거가 없으면 AI가 "(근거 필요)"를 붙인다.
스펙표나 검사 결과가 있을 때만 숫자를 쓴다.

그러니까 "100% 자동화"의 뜻은 이거다.

초안 100%를 AI가 뽑는다.
최종 승인은 사람이 한다.
공장이 찍어내고, 사람이 검수한다.

## 7. 공장에 매뉴얼을 건다

사과를 2~3번 돌렸다.
그 다음 헤드폰을 돌렸다.

느꼈다.
톤이 다르다.
사과에서는 "친절한 말투"였는데, 헤드폰에서는 "딱딱한 설명체"가 나왔다.
배송 안내도 매번 다른 형식으로 나온다.
금지 표현을 잡아내는 것도 빠지는 게 있다.

이유는 간단했다.

규칙이 내 머릿속에만 있었다.

"우리 브랜드는 이런 톤이야."
"배송 안내는 이 형식으로 써야 해."
"이 카테고리에서는 이런 표현 쓰면 안 돼."

이걸 내가 기억하고 있으면, 매번 다르게 나온다.
파일에 적어두면, 매번 같게 나온다.

그래서 매뉴얼을 만들었다.

| 매뉴얼 | 하는 일 |
|--------|--------|
| 톤앤매너 | "이 문체로 써. 이건 쓰지 마." |
| 섹션 규칙 | 각 블록에서 할 말, 하지 말 말 |
| 가격/정책 | 가격 표기법, 배송/교환/환불 템플릿 |
| 검수 기준 | 과장/금지 표현/필수 고지 체크리스트 |

이 파일들을 공장에 거는 거다.
AI가 초안을 만들기 전에 매뉴얼을 먼저 읽는다.
그러면 톤도, 형식도, 검수 기준도 매번 같다.

머릿속에 있으면 기준이다.
파일에 있으면 시스템이다.

담당자가 바뀌어도 같은 결과.
AI 모델이 바뀌어도 같은 결과.
매뉴얼이 있으니까.

사과 공장에 헤드폰 재료를 넣으면?
헤드폰 초안이 나온다.
카테고리가 달라지면 매뉴얼을 하나 추가하면 된다.
전자제품이면 "KC 인증 필수 고지" 매뉴얼을 건다.
식품이면 "원산지/유통기한 필수 고지" 매뉴얼을 건다.

공장은 그대로. 매뉴얼만 바꾼다.

## 8. 5일이면 공장이 돌아간다

여기까지 읽고 "이거 어렵겠다" 싶으면.

|-----|------|------|
| 1일차 | 상품 1개 골라서 재료 한 장 만들기 | 10분 |
| 2일차 | 지시서 붙여넣고 첫 실행 | 15분 |
| 3일차 | 질문 5개 답하고, 두 번째 실행 | 15분 |
| 4일차 | 검수에서 반복 걸리는 항목 → 매뉴얼에 추가 | 10분 |
| 5일차 | 다른 상품으로 같은 공장 돌려보기 | 15분 |

5일이면 공장이 돌아간다.
6일차부터는 상품 하나에 30분이다.

여기까지가 기획실이다.
카피도 나오고, 배치도 나오고, 검수도 된다.

근데 아직 하나가 빠졌다.

---

## 9. 텍스트는 나왔다. 근데 페이지가 아니다.

파일 11개를 열었다.
카피도 있다. 배치도 있다. 검수도 됐다.

근데 스마트스토어에 올릴 수 있나?
아직이다.

카피덱은 마크다운 파일이다.
와이어프레임은 텍스트로 된 설명이다.
이미지 프롬프트는 "이런 사진을 찍어라"는 지시일 뿐이다.

고객이 보는 건 파일이 아니다.
고객이 보는 건 페이지다.

전반부는 공장의 기획실이었다.
설계도를 그리고, 부품을 만들었다.

후반부는 조립 라인이다.
부품을 가져와서, 눈에 보이는 페이지로 만든다.

[캡처: 카피덱(텍스트) vs 완성된 상세페이지(이미지) 나란히 비교]

---

## 10. 조립 라인을 붙인다

도구는 2개다.

**레이아웃 기계.**
이름은 Pencil이다.
와이어프레임을 읽고, 프레임을 짜고, 카피를 배치하고, 색을 입힌다.
한글이 깨지지 않는다.

**사진 기계.**
이름은 Gemini다.
이미지 프롬프트를 읽고, 사진을 만든다.
제품 배경, 분위기 이미지, 라이프스타일 컷.

왜 나누는가.

"전체를 이미지 한 장으로 만들면 안 되나?"
안 된다.
글자가 뭉개진다. 한글이 깨진다. 수정하려면 처음부터 다시 만들어야 한다.

나누면 다르다.
텍스트는 레이아웃 기계가 찍는다. 정확하다.
사진은 사진 기계가 찍는다. 예쁘다.
수정은? 텍스트만 바꾸면 된다. 사진만 바꾸면 된다.
전체를 다시 만들 필요 없다.

이게 조립 라인이다.
부품별로 다른 기계가 처리한다.

---

## 11. 부품이 조립된다

전반부에서 만든 11개 파일.
이 중 6개가 조립 라인에 직접 들어간다.

| 전반부 파일 | 조립 라인에서 하는 일 |
|-------------|---------------------|
| 디자인 리서치 | 레퍼런스 패턴 → 섹션 구성/블록 배치 기준 |
| 섹션 기획 | 프레임 5개 생성 (Hero/USP/Proof/FAQ/CTA) |
| 카피 초안 | 헤드라인, 본문, 불릿, CTA 버튼 텍스트 배치 |
| 블록 배치 | 각 섹션 안에서 블록 위치 결정 |
| 색상 | 배경색, 글자색, 강조색 적용 |
| 이미지 지시 | 사진 기계에 전달할 프롬프트 |

사과로 해봤다.

카피 초안에서 Version A를 골랐다.
헤드라인: "2kg(10과) 부사 사과, 한 박스로 준비."
불릿 3개: 구성, 원산지, 배송.
CTA: "구매 정보 확인."

색상 파일에서 컬러를 가져왔다.
배경: 따뜻한 크림색.
강조: 빨간색 (사과니까).
글자: 검은색.

레이아웃 기계가 프레임을 짰다.
5개 섹션이 세로로 쌓인다.
각 섹션에 텍스트가 들어간다.
이미지가 들어갈 자리에는 회색 사각형이 놓인다.

[캡처: 텍스트만 채워진 상태 — 이미지 슬롯은 회색]

회색 사각형마다 이름표가 있다.
`IMG-HERO-01`. `IMG-PROOF-01`. `IMG-CTA-01`.

이 이름표가 전반부와 후반부를 잇는 열쇠다.
와이어프레임에 "여기에 IMG-HERO-01"이라고 적혀 있었다.
이미지 프롬프트에도 "IMG-HERO-01: 박스 + 사과 정면샷"이라고 적혀 있었다.
같은 이름표로 연결된다.

사진 기계가 프롬프트를 받는다.
"박스에 담긴 부사 사과, 위에서 내려다보는 구도, 자연광."
사진이 돌아온다.
회색 사각형이 사과 사진으로 바뀐다.

[캡처: 이미지가 채워진 Hero 섹션]

---

## 12. 사진 기계를 돌린다

여기서 중요한 거.

사진 기계는 보조다.
제품 사진을 "만들어내는" 게 아니다.

사진 기계가 만드는 것:
- 배경 이미지 (깔끔한 촬영 느낌)
- 라이프스타일 컷 (사과가 놓인 주방)
- 분위기 보정 (조명, 그림자, 색감)

사진 기계가 만들지 않는 것:
- 실제 제품 사진
- 라벨 사진
- 당도 측정 사진

왜?

전반부에서 배운 원칙이 여기서도 적용된다.

**"모르는 걸 적지 마라."**
텍스트에서는 이랬다.

**"없는 제품을 만들지 마라."**
이미지에서도 같다.

촬영 목록이 다리 역할을 한다.
"이건 AI가 만든다" — 배경, 분위기.
"이건 사람이 찍는다" — 실제 제품, 라벨, 측정.

사과 Proof 섹션을 보자.
좌측: 라벨 이미지. AI가 "라벨 클로즈업"을 만들었다.
우측: 당도 측정. **회색 그대로다.** "근거 필요"라고 적혀 있다.

[캡처: Proof 섹션 — 좌측 이미지 있음, 우측 회색 플레이스홀더]

이게 정직한 빈칸이다.
당도 13 brix를 넣고 싶으면, 측정 사진을 찍어서 넣으면 된다.
사진이 없으면? 빈칸으로 둔다.
AI가 "당도 측정하는 척"하는 사진을 만들지 않는다.

빈칸이 거짓보다 낫다.
텍스트에서도 그랬고, 이미지에서도 그렇다.

---

## 13. 시각 검수

텍스트 검수가 있었다.
"최고"를 잡고, 근거 없는 수치를 막고, TODO를 표시했다.

시각 검수도 있다.
같은 원리다.

| 확인 항목 | 기준 |
|----------|------|
| 텍스트 읽히나? | 폰트 14px 이상, 배경과 대비 충분 |
| 한글 깨지지 않았나? | 모든 텍스트 육안 확인 |
| 빈 이미지 슬롯 남았나? | TODO로 표시, 촬영 목록과 대조 |
| 컬러가 팔레트에서 벗어나지 않았나? | 색상 파일과 비교 |
| 모바일에서 잘리지 않나? | 가로 스크롤 없음 확인 |

사과 페이지를 검수했다.

문제 하나 발견.
Hero 헤드라인이 길었다. "2kg(10과) 부사 사과, 한 박스로 준비."
모바일에서 2줄로 넘어간다. 18자 이내 권장인데 20자다.

수정: "부사 사과, 한 박스로 준비."
카피 초안 파일을 고치고, 조립 라인을 다시 돌렸다.
이제 한 줄에 들어간다.

[캡처: 수정 전(2줄) vs 수정 후(1줄)]

전반부와 같다.
1차에서 문제를 찾고, 파일을 고치고, 다시 돌린다.
반복이 핵심이다.

## 14. 반복한다. 페이지가 나온다.

사과 공장을 처음부터 끝까지 돌렸다.

| 단계 | 할 일 | 소요 |
|------|------|------|
| 1 | 재료 한 장 (제품 정보) | 10분 |
| 2 | 공장 1차 가동 → 텍스트 11개 | 10분 |
| 3 | 질문 5개 답변 + 2차 가동 | 15분 |
| 4 | 조립 라인 → 페이지 초안 | 15분 |
| 5 | 시각 검수 + 수정 | 10분 |

합계: 약 1시간.

기존: 텍스트만 3시간 + 디자인 외주.
지금: 텍스트 + 디자인 + 이미지까지 1시간.

[캡처: 완성된 사과 상세페이지 전체]

같은 공장에 헤드폰 재료를 넣으면?
헤드폰 페이지가 나온다.
폼보드를 넣으면?
폼보드 페이지가 나온다.

재료만 바꾼다. 공장은 그대로다.
텍스트도 나오고, 페이지도 나온다.

## 15. 5일 + 2일이면 시각 공장까지

| 일차 | 할 일 | 소요 |
|-----|------|------|
| 1일차 | 상품 1개 골라서 재료 한 장 만들기 | 10분 |
| 2일차 | 지시서 붙여넣고 첫 실행 | 15분 |
| 3일차 | 질문 5개 답하고, 두 번째 실행 | 15분 |
| 4일차 | 검수에서 반복 걸리는 항목 → 매뉴얼에 추가 | 10분 |
| 5일차 | 다른 상품으로 같은 공장 돌려보기 | 15분 |
| **6일차** | **조립 라인 첫 실행: 텍스트 → 페이지** | **20분** |
| **7일차** | **사진 생성 + 시각 검수 + 수정** | **20분** |

7일이면 텍스트 공장 + 시각 공장이 돌아간다.
8일차부터는 상품 하나에 1시간이다.

---

정리하면.

공장에 필요한 건 4가지다.

**1. 재료 한 장** — 제품 정보를 모은다. 모르는 건 비운다.
**2. 지시서** — "이 11개 파일을 만들어줘" + "이 파일로 페이지를 조립해줘."
**3. 매뉴얼** — 톤, 금지 표현, 정책, 시각 검수 기준을 파일로 적어둔다.
**4. 조립 도구** — 레이아웃 기계(Pencil) + 사진 기계(Gemini).

이 4가지가 파일로 있으면, 텍스트도 나오고 페이지도 나온다.
상품이 바뀌면 재료만 바꾼다.
공장은 그대로다.

---

이 글에서 사용한 도구는 Claude Code, Pencil, Gemini다.
근데 핵심은 도구가 아니다.

재료 한 장.
지시서.
매뉴얼.
조립 도구.

이 4가지를 파일로 만드는 것.
그게 공장이다.
