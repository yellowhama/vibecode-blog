## 에피소드 상세

### EP01: "그냥 만들면 되지"

**소스**: Act 1-1 (스펙의 필요성 인식), Act 1-2 (스펙 없는 코딩의 결과)

#### 세그먼트 구성

| 세그먼트 | 시간 | 내용 |
|---------|------|------|
| HOOK | 20s | Vee "완성!" 자축 → 화면에 에러 폭포 → 폭발 이펙트 |
| SITCOM ACT 1 | 75s | Vee 바이브코딩 몽타주 (자신만만) → 앱 데모 → 터짐 → Bee 등장 "스펙이 뭔데?" → Vee "???" |
| EXPLAINER | 100s | 설계도 메타포: 건물 올리기 (with) vs 그냥 쌓기 (without) → No-spec coding 무너짐 → MVP 스케이트보드 |
| SITCOM ACT 2 | 75s | Vee 설계도 따라 다시 시도 → 코드가 정리됨 → Bee "...뭐 나쁘진 않네" |
| ENDING | 20s | Vee 벽에 작은 설계도 핀 꽂음 → Bee 슬쩍 쳐다봄 → 다음편 떡밥: "근데 이 스펙... 맞긴 한 거야?" |

**쇼츠 후보**:
1. HOOK 전체 (20s) — Vee 자축 → 폭발
2. EXPLAINER 중 "설계도 없이 쌓기 → 무너짐" (15s)
3. Bee 첫 등장 + "스펙이 뭔데?" (15s)

#### 해설 메타포 (라이브러리 참조)

| 순서 | 개념 | 메타포 ID | 시간 |
|------|------|----------|------|
| 1 | Spec | Act1-#1 (설계도) | 15s |
| 2 | No-spec coding | Act1-#2 (무작위 쌓기) | 10s |
| 3 | Codebase | Act1-#3 (도시 전경) | 15s |
| 4 | MVP | Act1-#9 (스케이트보드) | 15s |
| | **소계** | | **55s** |

+ 전환 연출 (진입 3s + 복귀 3s) + 내레이터 설명 간 pause = ~100s

### EP02: "고치면 더 터져"

**소스**: Act 1-3 (디버깅 한계), Act 1-4 (프롬프트와 스펙의 차이)

| 세그먼트 | 시간 | 내용 |
|---------|------|------|
| HOOK | 20s | Vee "이거 하나만 고치면 돼" → 3개 에러 → 5개 에러 → 12개 에러 |
| SITCOM ACT 1 | 80s | Vee 디버깅 루프 → Bee한테 도움 요청 → Bee "니가 만든 건 니가 고쳐" → Vee 프롬프트만 바꿔봄 |
| EXPLAINER | 100s | 구두 주문 vs 서면 주문 메타포 → Prompt 흐릿해짐 vs Spec 선명 → Bug 균열 확산 |
| SITCOM ACT 2 | 70s | Vee 프롬프트 대신 스펙으로 정리 → 에러 줄어듦 → Bee 살짝 고개 끄덕 |

**쇼츠 후보**:
1. HOOK (에러 카스케이드) (20s)
2. 구두 주문 → 엉뚱한 음식 (15s)
3. Vee "이거 하나만..." → Bee "..." 리액션 (20s)
