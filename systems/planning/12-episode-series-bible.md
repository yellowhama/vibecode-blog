## Phase 3 이후: 자연 확장

- **AI 뉴스 리뷰**: 새 모델, 새 도구 (Claudius Papirus 방식)
- **실전 프로젝트 따라하기**: 시청자와 같이 만들기
- **시청자 질문 기반 에피소드**: 댓글/커뮤니티 질문 → 에피소드
- **트렌드 반응**: 새 AI 도구 출시 → Vee가 써보는 에피소드

## 캐릭터 아크 (Phase 1-2)

### Vee의 성장

| 구간 | EP | 패턴 | 핵심 변화 |
|------|-----|------|----------|
| 순수 호기심 | 01-02 | "이거 뭐야? 해볼래!" | 처음 만져봄. 궁금해서 시작. |
| 첫 벽 | 03-04 | "어? 왜 이러지?" | 호기심이 혼란으로. 질문이 깊어짐. |
| 구조 발견 | 05-06 | "아 이렇게 정리하는 거구나" | 패턴을 발견. 개념을 행동으로. |
| 자립 | 07-08 | "이제 혼자 해볼게" | 아직 서툴지만 방향은 맞음. |

### Bee의 변화

| 구간 | EP | 패턴 | 핵심 변화 |
|------|-----|------|----------|
| 귀찮음 | 01-02 | (팻말: "NOT MY PROBLEM") | 무시. 자기 집만 걱정. |
| 못 참음 | 03-04 | (팻말: "...FINE") | 틀린 거 보면 못 참아서 끼어듦. |
| 인정 | 05-06 | (팻말으로 도움) | 같이 문제 풀기 시작. |
| 은근 뿌듯 | 07-08 | (0.5초 미소 → 바로 무표정) | Vee 성장에 살짝 감동. 빨리 숨김. |

### 관계 발전

```
EP01: Bee 무시 (Vee 코드 = Bee한테 위험)
EP02: Bee 마지못해 반응 (Vee가 너무 틀려서 못 참음)
EP03: 첫 팻말 도움 (Bee: "에러는 결정 문제")
EP04: 약간의 패턴 (Vee가 Bee 팻말을 기다림)
EP05: 같이 정리 (역할 분담 시작)
EP06: 파트너 (Bee가 먼저 팻말 들고 옴)
EP07: 위기 → 결속 (같이 터지고 같이 수습)
EP08: 팀 (Vee 혼자 해보겠다 → Bee 은근 뿌듯)
```

## 에피소드 상세

### EP01: "바이브코딩이 뭐야?"

**질문**: AI한테 시키면 코딩 아닌가? 바이브코딩이 따로 있어?

| 세그먼트 | 시간 | 내용 |
|---------|------|------|
| 질문 | 12s | "바이브코딩이 뭔데?" — 텍스트 + Vee 궁금한 표정 |
| 상황 | 75s | Vee가 AI한테 "앱 만들어줘" → 뭔가 나옴 → "어? 이게 바이브코딩?" → 돌아가긴 함 → 고치려고 하니까 "어?" |
| 설명 | 100s | AI가 대신 코딩 ≠ 바이브코딩. 같이 만드는 것. 브라우저 Claude (대화) vs Claude Code (코드). 다이어그램: 지시→결과 vs 대화→협업 |
| 적용 | 45s | Vee가 "같이 만드는" 방식으로 재시도. 결과가 다름. Bee 슬쩍 쳐다봄. |
| 다음 질문 | 10s | "근데... 뭘 만들라고 해야 돼?" |

**쇼츠 후보**:
1. 설명 중 "대신 vs 같이" 다이어그램 (30s)
2. Vee "어? 이게 바이브코딩?" 리액션 (15s)

---

### EP02: "뭘 만들라고 해야 돼?"

**질문**: AI한테 뭐라고 말해야 원하는 게 나와?

| 세그먼트 | 시간 | 내용 |
|---------|------|------|
| 질문 | 12s | "뭘 만들라고 해야 돼?" |
| 상황 | 80s | Vee가 AI한테 두루뭉술하게 시킴 → 엉뚱한 결과 → 더 자세히 말함 → 여전히 다름 → Bee 팻말: "SPEC" |
| 설명 | 100s | 스펙 = 4가지 질문 (뭘/왜/어떻게/뭘로). 짜증 → 스펙 되는 과정. 다이어그램: 두루뭉술한 지시 vs 4가지 질문 |
| 적용 | 40s | Vee 4가지 질문으로 정리 → AI한테 줌 → 결과가 의도에 가까움 |
| 다음 질문 | 10s | "좋아... 근데 만들었는데 왜 터져?" |

**쇼츠 후보**:
1. 설명 중 "4가지 질문" 다이어그램 (30s)
2. Vee 두루뭉술 지시 → 엉뚱한 결과 (20s)

---

### EP03: "만들었는데 왜 터져?"

**질문**: 에러가 떴는데 이게 뭔 소리야?

| 세그먼트 | 시간 | 내용 |
|---------|------|------|
| 질문 | 12s | "만들었는데 왜 터져?" |
| 상황 | 75s | Vee 앱 돌려봄 → 에러 → "코드가 잘못됐나?" → 고침 → 다른 데서 터짐 → Bee 팻말: "코드 아님. 결정." |
| 설명 | 110s | 에러 = 코드 문제 X, 결정 문제 O. 에러 메시지 읽는 법 기초. 다이어그램: 에러 → 추적 → 결정 지점 발견 |
| 적용 | 40s | Vee 에러 메시지 따라감 → 결정 지점 발견 → "아... 여기서 잘못됐구나" |
| 다음 질문 | 10s | "근데 하나 고치면 더 터지는데?" |

**쇼츠 후보**:
1. 설명 중 "에러 추적" 다이어그램 (35s)
2. Bee 팻말 "코드 아님. 결정." (15s)

### EP04: "고치면 더 터지는데?"

**질문**: 하나 고쳤는데 왜 세 개가 터져?

| 세그먼트 | 시간 | 내용 |
|---------|------|------|
| 질문 | 12s | "고치면 더 터지는데?" |
| 상황 | 75s | Vee 하나 고침 → 세 개 터짐 → 세 개 고침 → 다섯 개 터짐 → Bee 도미노 팻말 |
| 설명 | 100s | 의존성 = 도미노. A가 B를 부르고 B가 C를 부름. 하나 건드리면 줄줄이. 다이어그램: 도미노 체인 + 연결 관계도 |
| 적용 | 45s | Vee 연결 관계 먼저 파악 → 올바른 순서로 고침 → 연쇄 반응 멈춤 |
| 다음 질문 | 10s | "파일이 너무 많은데... 어디가 어딘지 모르겠어" |

**쇼츠 후보**:
1. 설명 중 "도미노 체인" 다이어그램 (30s)
2. Vee "하나 고침 → 세 개 터짐" 반복 (20s)

---

### EP05: "파일이 너무 많은데?"

**질문**: 프로젝트가 커졌는데 어디가 어딘지 모르겠어.

| 세그먼트 | 시간 | 내용 |
|---------|------|------|
| 질문 | 12s | "파일이 너무 많은데?" |
| 상황 | 70s | Vee 파일 목록 스크롤 → 끝이 안 보임 → 뭘 고쳐야 할지 모름 → Bee 지도 팻말 |
| 설명 | 110s | 구조 = 도시 지도. 비슷한 것끼리 모으기. 도메인 = 동네. 다이어그램: 랜덤 파일들 → 동네별 정리 |
| 적용 | 40s | Vee 파일을 동네별로 정리 → 길이 보임 → Bee "이쪽이었어" |
| 다음 질문 | 10s | "정리는 했는데... 이게 맞는지 어떻게 알아?" |

**쇼츠 후보**:
1. 설명 중 "도시 지도" 다이어그램 (30s)
2. Vee 무한 스크롤 (15s)

### EP06: "테스트가 뭐야?"

**질문**: 테스트? 그거 개발자만 하는 거 아니야?

| 세그먼트 | 시간 | 내용 |
|---------|------|------|
| 질문 | 12s | "테스트가 뭐야?" |
| 상황 | 75s | Vee 코드 바꿈 → 잘 됨 → 다음 날 안 됨 → "어제는 됐는데?" → Bee 팻말: "TEST" |
| 설명 | 100s | 테스트 = 안전망. "터지기 전에 아는 것." 서커스 안전망 비유. 다이어그램: 코드 변경 → 테스트 통과/실패 → 배포 판단 |
| 적용 | 40s | Vee 간단한 테스트 작성 → Red → 고침 → Green → "이거였어!" |
| 다음 질문 | 10s | "좋아, 근데 배포는 어떻게 해?" |

**쇼츠 후보**:
1. 설명 중 "안전망" 다이어그램 (30s)
2. Vee Red → Green 리액션 (20s)

### EP07: "배포는 어떻게 해?"

**질문**: 내 컴퓨터에서 되는데 남한테 어떻게 보여줘?

| 세그먼트 | 시간 | 내용 |
|---------|------|------|
| 질문 | 12s | "배포는 어떻게 해?" |
| 상황 | 75s | Vee "이거 봐봐" → 친구: "안 되는데?" → Vee "내 컴에선 되는데..." → Bee 한숨 |
| 설명 | 100s | 로컬 vs 프로덕션. 왜 다르게 터지나. 다이어그램: 내 방(로컬) → 밖(서버). 환경 차이. |
| 적용 | 40s | Vee 환경 맞추기 → 배포 → 친구: "오 된다!" |
| 다음 질문 | 10s | "된다! 근데... 이걸로 뭔가 할 수 있나?" |

**쇼츠 후보**:
1. 설명 중 "로컬 vs 프로덕션" 다이어그램 (30s)
2. "내 컴에선 되는데..." (15s)

### EP08: "이걸로 돈 벌 수 있어?"

**질문**: 바이브코딩으로 진짜 뭔가 만들 수 있어?

| 세그먼트 | 시간 | 내용 |
|---------|------|------|
| 질문 | 12s | "이걸로 돈 벌 수 있어?" |
| 상황 | 75s | Vee "앱 만들었는데 이걸로 뭐 하지?" → 거대한 계획 세움 → 현실: 아무도 안 씀 → Bee 스케이트보드 팻말 |
| 설명 | 100s | MVP = 스케이트보드. 자동차 만들지 마. 가장 작은 것부터. 다이어그램: 스케이트보드 → 킥보드 → 자전거 → 자동차 |
| 적용 | 45s | Vee 최소 기능만 남김 → 누군가 씀 → "오... 된다?" → Bee 0.5초 미소 → 무표정 |
| 다음 질문 | 10s | Phase 2 예고 또는 뉴스 리뷰 시리즈로 연결 |

**시즌 마무리**: Vee가 EP01 질문 "바이브코딩이 뭐야?"를 다시 떠올림 → 이제 답할 수 있음. 원점 회귀 but 변화.

**쇼츠 후보**:
1. 설명 중 "스케이트보드→자동차" 다이어그램 (30s)
2. Bee 0.5초 미소 (15s)
