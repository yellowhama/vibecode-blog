# 유튜브 채널 포맷 바이블

> **SSOT**: 에피소드 구조, 타이밍, 비주얼 모드, 전환 규칙.
> **채널 아이덴티티**는 `16-channel-identity.md` 참조.

## 에피소드 구조 (3.5-5분)

**StoryBots + Kurzgesagt 하이브리드: 질문 기반 구조**

모든 에피소드는 시청자의 진짜 질문 하나에 답한다.

### 세그먼트 템플릿

| # | 세그먼트 | 시간 | 역할 |
|---|---------|------|------|
| 1 | **질문** | 10-15s | "바이브코딩이 뭔데?" — 시청자가 실제로 하는 질문으로 시작 |
| 2 | **상황** | 60-90s | Vee가 이 질문과 만나는 맥락. 뭔가 해보다가 "어?" 하는 순간 |
| 3 | **설명** | 90-120s | 내레이터 + 다이어그램/시각화로 개념 설명. 핵심 데이터 포함 |
| 4 | **적용** | 30-60s | Vee가 이해한 걸 적용. 결과가 보임 |
| 5 | **다음 질문** | 10-15s | 이 답에서 자연스럽게 나오는 다음 질문 = 다음 에피소드 떡밥 |

**총 시간**: 3.5분 (최소) ~ 5분 (최대). **짧게. 리텐션 우선.**

### 기존 대비 변경

| 기존 | 신규 | 변경 이유 |
|------|------|----------|
| HOOK (결과 먼저) | **질문** (질문 먼저) | 결과 보여주기 → 시청자 질문으로 공감 진입 |
| SITCOM ACT 1 (삽질 코미디) | **상황** (호기심 맥락) | 실패로 시작 → 호기심으로 시작 |
| EXPLAINER | **설명** (유지, 강화) | 데이터 밀도 ↑ |
| SITCOM ACT 2 (해결 코미디) | **적용** (축소) | 설명의 증명으로만 |
| ENDING (떡밥) | **다음 질문** (축소) | 다음편 연결만 |

### 타이밍 규칙

- **질문**: 3초 안에 질문 텍스트가 화면에 뜸
- **상황**: 15초 이내 Vee의 "어?" 순간 도달
- **설명**: 전환 연출 후 시작. 데이터 포인트 2개+ 필수.
- **적용**: 설명 반복 금지. 행동으로만 보여줌.
- **다음 질문**: 10초 넘기지 않음. 짧게.

## 캐릭터 역할

> 캐릭터 상세 설정은 `16-channel-identity.md` 참조.

### Vee — 시청자 아바타 (호기심)

- 질문을 던지는 쪽. "어? 왜 이러지?"로 시작.
- **대사 없음**. 비주얼 리액션 + 팻말만.
- 상황/적용 세그먼트에 등장. 설명 세그먼트에는 등장 안 함.
- 감정 루프: 호기심 → 실험 → 혼란 → 이해 → 발견

### Bee — 이해관계자 (정확함)

- Vee 코드 위에 살고 있음. 코드 터지면 집이 터짐.
- 핵심 한 줄 + 팻말/다이어그램으로만 개입.
- **대사 없음**. 비주얼 리액션만.
- 길게 설명하지 않음. 못 참아서 끼어들 뿐.

### 내레이터 — 전 세그먼트 주도

- 차분하고 빠른 목소리. Kurzgesagt 톤 + Fireship 속도.
- **모든 세그먼트에서** 정보를 전달한다.
- 시청자는 내레이터 음성만으로도 에피소드 내용을 100% 이해할 수 있어야 한다.
- 대본은 **영어**로 작성.
- 립싱크 없음 → 음성은 100% 내레이터.

## 정보 경로 설계 (Information Path)

대본 작성 전, 반드시 정보 경로를 먼저 설계한다:

```
시청자가 아는 것 (출발점)
       ↓
질문: 시청자의 궁금증
       ↓
상황: 왜 이 질문이 중요한지
       ↓
설명: 핵심 개념 (데이터 포함)
       ↓
적용: 이해한 걸 적용한 결과
       ↓
다음 질문: 새로운 궁금증 (도착점 = 다음 출발점)
```

규칙:
- 한 번에 하나만 전달
- 아는 것 → 모르는 것 순서
- **Curse of Knowledge 체크**: "이 문장을 바이브코딩 안 해본 사람이 이해하는가?"

## 비주얼 모드

### 모드 A: 캐릭터 장면 (질문, 상황, 적용, 다음 질문)

- **스타일**: 2D flat vector (Kurzgesagt 계열)
- **캐릭터**: Vee (Cyan), Bee (Amber)
- **배경**: 다크 (#0D1B2A) + 밝은 캐릭터
- **카메라**: 캐릭터 중심. 단순한 구도.

### 모드 B: 설명 (설명 세그먼트)

- **스타일**: Kurzgesagt식 인포그래픽 + ByteByteGo 다이어그램
- **캐릭터**: 없음. 추상 도형/다이어그램만.
- **배경**: 다크 (#0D1B2A)
- **색감**: 토픽별 팔레트 (Kurzgesagt 방식)
- **요소**: 기하학적 도형, 화살표, 단계별 애니메이션

### 모드 C: 코드 데모 (설명 또는 적용 내 삽입)

- **스타일**: Fireship 스타일 — 다크 터미널 + 하이라이트
- **코드**: 최소한만. 개념 이해에 필요한 부분만.
- **시간**: 10-15초 이내

### 스타일 전환 = 정보 타입 전환

```
캐릭터 장면 → 다이어그램 → 코드 데모 → 캐릭터
```

전환 시:
1. 내레이터가 전환 큐를 준다 (예: "But why does this keep happening?")
2. 화면 요소가 다이어그램으로 변형 (또는 컷 전환)
3. 전환 구간: 1-2초 (빠르게)

## 내레이션 규칙

| 모드 | 화자 | 스타일 |
|------|------|--------|
| 캐릭터 장면 | **내레이터 (V.O.) only** | 상황 설명 + 질문 |
| 설명 | **내레이터 (V.O.) only** | 비유 중심, 데이터 포함, 차분하고 빠름 |
| 코드 데모 | **내레이터 (V.O.) only** | 짧고 정확한 설명 |

> **립싱크 없음 → 음성은 100% NARRATOR (V.O.)**. 캐릭터는 비주얼 리액션만.

## 듀얼 포맷

| 포맷 | 길이 | 용도 |
|------|------|------|
| **메인 에피소드** | 3.5-5분 | 커리큘럼 에피소드. 위 5세그먼트 구조 |
| **쇼츠** | 30-60s | 설명 세그먼트만 잘라서 독립 쇼츠 |
| **뉴스 리뷰** | 3-5분 | 새 AI 도구/뉴스 리뷰 (Claudius Papirus 방식) |

### 쇼츠 추출 규칙

- 에피소드당 **2-3개** 쇼츠 후보 사전 지정
- 추출 우선순위:
  1. **설명 핵심 다이어그램** (30-45s) — 독립적으로 이해 가능한 개념
  2. **질문 + 답** (15-30s) — 질문 던지고 바로 핵심 답
  3. **Vee+Bee 케미** (15-30s) — 비주얼 하이라이트
- 매니페스트에 `shorts_candidate: true` 플래그로 마킹

### 뉴스 리뷰 구조

커리큘럼 이후 자연스럽게 확장. Claudius Papirus 방식.

| # | 세그먼트 | 시간 |
|---|---------|------|
| 1 | 뉴스 요약 | 15-30s |
| 2 | "이게 왜 중요해?" | 60-90s |
| 3 | "바이브코더한테 뭐가 달라져?" | 60-90s |
| 4 | 한 줄 요약 | 10s |

## 비주얼 코미디 가이드

캐릭터 대사가 없으므로 **비주얼이 핵심**.

| 기법 | 설명 | 예시 |
|------|------|------|
| 팻말/간판 | 화면에 글자 등장 | Bee 팻말: "NOPE", "TRY AGAIN" |
| 표정 변화 | 캐릭터 표정 전환 | Vee 눈 커짐 (발견), Bee 한숨 |
| 대조 컷 | 기대 vs 현실 | 상상: 깔끔한 코드 / 현실: 에러 |
| 다이어그램 반응 | 설명 중 시각적 강조 | 화살표가 빨갛게 변함, 도형 폭발 |
