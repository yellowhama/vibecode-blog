# 유튜브 채널 포맷 바이블

## 채널 정체성

- **장르**: 테크 시트콤 + 해설 (롱폼 하이브리드)
- **타겟**: Vibe Coder — 코드 못 읽는데 AI로 만드는 사람
- **차별점**: 애니메이션 캐릭터 + 테크 코미디 = 유튜브 전체에서 0개 채널
- **톤**: 코미디 70% + 교육 30%. 웃기면서 배운다.

## 에피소드 구조 (5-8분 롱폼)

모든 에피소드는 5단계 세그먼트로 구성된다.

### 세그먼트 템플릿

| # | 세그먼트 | 모드 | 시간 | 역할 |
|---|---------|------|------|------|
| 1 | **HOOK** | 시트콤 | 15-30s | Vee 삽질 하이라이트. 결과 먼저 보여주기. 궁금증 유발. |
| 2 | **SITCOM ACT 1** | 시트콤 | 60-90s | Vee가 문제 만남. 내레이터가 상황 설명. 비주얼 코미디. |
| 3 | **EXPLAINER** | 해설 | 90-120s | 내레이터가 추상 시각화로 핵심 개념 설명 |
| 4 | **SITCOM ACT 2** | 시트콤 | 60-90s | Vee가 이해하고 해결. 비주얼로 변화 보여줌. |
| 5 | **ENDING** | 시트콤 | 15-30s | 교훈 + 다음편 떡밥 |

**총 시간**: 4분 (최소) ~ 8분 (최대)
**권장**: 5-6분 (리텐션 최적)

### 타이밍 규칙

- HOOK은 **3초 안에** 시각적 충격 (앱 폭발, 에러 쏟아짐)
- SITCOM ACT 1 시작 **30초 이내** 첫 웃음 포인트
- EXPLAINER 진입 시 **전환 연출** 필수 (아래 참조)
- SITCOM ACT 2는 EXPLAINER 내용을 **행동으로** 보여줌 (설명 반복 금지)
- ENDING은 **짧게** — 늘어지면 이탈

## 캐릭터 역할

### Vee (Ivy Burr) — 감정이입 앵커

- 시청자의 아바타. 시청자가 하는 실수를 Vee가 한다.
- **항상 실수하는 쪽**. 천재가 아니라 열심히 하는 쪽.
- 감정 스펙트럼: 자신만만 → 혼란 → 좌절 → 이해 → 성취
- **대사 없음**. 음성은 전부 내레이터. 캐릭터는 비주얼 리액션만.
- 비주얼: 눈=달러(흥분), 멘붕 표정(에러), 자축 댄스(성공), 팻말 들기
- **시트콤 파트에만 등장**. 해설 파트에는 나오지 않음.

### Bee — 마지못해 가르치는 사이드킥

- 지친 아저씨 꿀벌. 내면은 시니어 개발자.
- Vee가 삽질할 때 비주얼로 끼어듦.
- 시트콤에서는 투덜+리액션 (비주얼만). 해설에서는 등장 안 함.
- 감정 스펙트럼: 짜증 → 한숨 → 마지못한 리액션 → 은근 뿌듯 (빨리 숨김)
- **대사 없음**. 음성은 전부 내레이터. 캐릭터는 비주얼 리액션만.
- 비주얼: 무표정, 간판/팻말 들기, 이단옆차기(극단적 교정)

### 내레이터 — 전 세그먼트 주도

- 차분하고 깔끔한 목소리. Kurzgesagt 내레이터 느낌.
- **모든 세그먼트에서** 정보를 전달한다. 시트콤/해설 구분 없이.
- 시청자는 내레이터 음성만으로도 에피소드 내용을 100% 이해할 수 있어야 한다.
- 내레이터가 스테이크(정보). 캐릭터는 양념(비주얼 코미디).
- 대본은 **영어**로 작성. 비유 중심 설명.
- 립싱크 없음 → 캐릭터 대사 없음 → 음성은 100% 내레이터.

## 정보 경로 설계 (Information Path)

대본 작성 전, 반드시 정보 경로를 먼저 설계한다:

```
시청자가 아는 것 (출발점)
       ↓
정보 1: 첫 번째 배움
       ↓
정보 2: 두 번째 배움
       ↓
...
정보 N: 최종 배움 (도착점)
```

규칙:
- 한 번에 하나만 전달
- 아는 것 → 모르는 것 순서
- 각 정보는 하나의 세그먼트에 매핑
- **Curse of Knowledge 체크**: "이 문장을 바이브코딩 안 해본 사람이 이해하는가?"

## 비주얼 코미디 가이드

캐릭터 대사가 없으므로 **비주얼 코미디가 핵심**. 각 시트콤 세그먼트에 최소 2개 비주얼 개그를 포함.

| 기법 | 설명 | 예시 |
|------|------|------|
| 표정 개그 | 캐릭터 표정 과장 | 눈=달러, 눈=하트, 멘붕 표정 |
| 팻말/간판 | 화면에 글자 등장 | "3 seconds later..." 자막, 경고 팻말 |
| 과장 리액션 | 물리적으로 날아감 | 이단옆차기, 의자에서 떨어짐 |
| 반복 개그 | 같은 패턴 3번 반복 | build → error → 멘붕 x3 |
| 대조 컷 | 기대 vs 현실 | 상상: 완벽한 앱 / 현실: 에러 폭탄 |

## 비주얼 모드

### 모드 A: 시트콤 (HOOK, SITCOM ACT 1/2, ENDING)

- **스타일**: 3D Pixar-like 렌더, subtle clay texture
- **캐릭터**: Vee, Bee (+ 향후 게스트)
- **배경**: Vee의 방/책상, 카페, 공원 등 일상 공간
- **색감**: 밝고 따뜻한 톤 (yellow hoodie 기준)
- **카메라**: 캐릭터 중심. MS(Medium Shot), CU(Close-Up) 위주.
- **렌더 파이프라인**: Flux Kontext (Vee) + Flux T2I (Bee) → Wan I2V

### 모드 B: 해설 (EXPLAINER)

- **스타일**: Kurzgesagt식 인포그래픽 애니메이션
- **캐릭터**: 없음. 추상 도형/메타포만.
- **배경**: 짙은 네이비 (#0D1B2A) 또는 다크 그레이
- **색감**: 볼드 채도 높은 색 (오렌지 #FF6B35, 시안 #00D4FF, 그린 #7AE582)
- **요소**: 기하학적 도형, 아이콘, 화살표, 모션 그래픽
- **카메라**: 탑다운 또는 아이소메트릭. 줌인/줌아웃 모션.
- **렌더 파이프라인**: Flux T2I (추상 키프레임) → Wan I2V 또는 모션 그래픽

### 프롬프트 기본 템플릿

## 전환 연출 (시트콤 ↔ 해설)

### 시트콤 → 해설 (진입)

1. 내레이터가 전환 큐를 준다 (예: "But why does this keep happening?")
2. Vee 책상 위 물건 **줌인** (컵, 연필, 모니터 등)
3. 물건이 **추상 도형으로 변형** (모핑 트랜지션)
4. 카메라 **풀백** → 해설 세계 (다크 배경 + 도형들)
5. 내레이터 보이스 시작

### 해설 → 시트콤 (복귀)

1. 해설 마지막 도형 **줌인**
2. 도형이 **실물 오브젝트로 변형** (역모핑)
3. 카메라 **줌아웃** → Vee 책상/방으로 복귀
4. Vee 비주얼 리액션 (이해한 표정)
5. Bee 비주얼 리액션 (팔짱/한숨)

### 기술적 구현

- 전환 구간: 2-3초
- Wan I2V로 모핑 효과 시도 (키프레임 A=실물, 키프레임 B=도형)
- 안 되면 컷 전환 + 사운드 이펙트로 대체

  3. **코미디 비트** (15-30초) — Vee+Bee 케미 하이라이트
- 쇼츠는 에피소드와 **별도 렌더 불필요** — 롱폼에서 구간 추출
- 매니페스트에 `shorts_candidate: true` 플래그로 마킹

### 대본 구조 — Claudius 공식 vs 우리 공식

```
[Claudius 공식]                    [우리 공식]
1. 뉴스 Hook (사건/논문)            1. HOOK (Vee 삽질 결과)
2. 텐션 설정 ("But...")            2. SITCOM ACT 1 (문제 발생)
3. 해설 본문 (논문 분석)            3. EXPLAINER (개념 시각화)

```

**차이**: Claudius = 순수 해설 (시트콤 없음). 우리 = 해설을 시트콤으로 감쌈.
**배울 것**: Hook의 "뉴스성". 우리도 HOOK에 실제 사건/트렌드 연결하면 바이럴 가능성 ↑
